Architecture C — audit before integrating the simplification policies (S5 P18)

Status: phase 1 report (audit, dependencies, plan). Base: master d16ae332 (PR #683, Architecture B, merged). Scope: what the rules of ExpressionSimplifier would have to declare and check to consume ExpressionSimplifierOptions, which anomalies block that, and in which order to integrate it. Related notes: BehaviorAnalysis.md (A), SimplificationPolicies.md (B), A10-ReflectionProvenance.md, the S5 deep audit (Utils/TODO-2026-11-04-s5-simplifier-deep-audit.md).

1. Contract decision (2026-11-05)

Taken before the design, at the user's request:

  1. The default policy is strictly preserved. Under ExpressionSimplifierOptions.Default the simplifier, and therefore ExpressionComparer.Default (whose internal simplifier uses the default), give exactly the results, user calls, exceptions and resource consumption of master before C. Verified by the S5 campaigns (§8).

  2. Category A improvements of the default go to a separate pull request with its own compatibility entry: the rewrites that are correct under every policy (F() + 0 -> F()), and the evaluations the P18-A analysis proves safe where the gate refuses them (invoked lambdas, blocks with local effects).

  3. Intrinsic admissibility is separated from the historical compatibility of the default. A rule is not admitted "only when the explicit policy grants a permission the default lacks": that would make the rules that are correct under every policy unreachable under every policy. Instead:

    • intrinsic admissibility of a rewrite = the permissions of the evaluations it actually drops, merges, duplicates or moves, under the instance's Options, plus the contextual conditions (B §3.3, §3.5, §3.6); a rewrite that changes no evaluation needs no permission;
    • historical admission = the ETC R1b gate (AllowsRules: operands inert by ExpressionEffectAnalysis), unchanged;
    • a node's rules run when the historical gate allows them (exactly as today); when it refuses, an audited rule may still run under its intrinsic admissibility, except under the default policy, which keeps the historical admission alone. That exception is a single switch (ExpressionSimplifier.UsesHistoricalAdmission): the category A pull request will remove it, without touching the rules. Its compatibility entry will be C-08: C-07 is already taken (ETC R2, replacing a runtime variable by anything but a parameter throws NotSupportedException).

    Consequence, documented as such: any explicit non-default policy leaves the historical-compatibility mode, so it also enables the category A rewrites of the audited rules, which require no permission and are correct under every policy. The three axes stay independent in what they relax (each lifts only its own flags of the permission table); leaving the compatibility mode is not a relaxation.

5. Design of the integration

5.1 Invariants

  • I-1 Permissions before structure. Outside the gate, a rule decides from the permissions before it compares, hashes, keys or memoizes an operand. So a node holding a custom reflection object (unknown code) never reaches the A10-B consumers through C.
  • I-2 Every affected evaluation, every operation. A rule asks the permission of each evaluation it actually drops, merges, duplicates or moves (B §3.6); a rewrite that changes none asks nothing.
  • I-3 No new exception, none at simplification time. Outside the gate a rule never throws for a zero divisor or an overflowing fold; it declines.
  • I-4 Derived rules stay behind the gate. Only the audited methods of ExpressionSimplifier run outside it.
  • I-5 Default unchanged. Under ExpressionSimplifierOptions.Default no rule runs outside the gate.

5.2 Mechanism (C1)

  • ExpressionTransformer.TryTransform: when AllowsRules(node) refuses, it asks once AllowsAuditedRulesOutsideGate(node) (base: false); if that also refuses, the loop stops exactly as today (same trace). Otherwise only the rules for which IsAuditedRule(method) holds are invoked, each with an ambient, thread-static "outside the gate" flag set for the duration of the call (saved and restored, so nested rules and comparer simplifications see their own admission); the other candidates are traced as rejected by the effect gate, without their signature being matched (a custom Match is user code, and a detailed trace must not run more of it than the untraced run).
  • ExpressionSimplifier: AllowsAuditedRulesOutsideGate is !UsesHistoricalAdmission (Options equal to the default); the audited set is a static set of method handles of its own rules.
  • Rule helpers: CanDropOperand(t) is true inside the gate (the gate proved t inert) and, outside it, CanDiscard of the behavior of t under Options, computed by the internal entry ExpressionBehaviorAnalysis.AnalyzeWithinOperation: it joins the running operation without opening a nested one nor validating t again; every analyzed node, rebuilt ones included, still consumes a structural visit and checks the stack.

5.3 Behavior analysis cost and caches

A drop analyzes the dropped operand once (Analyze: ≈ 40 ns + 12–25 ns per node, joining the running operation, counted in its visit budget). Analyzing a subtree out of its lexical context is conservative (a parameter bound outside it is read as mutable state, a write to it as a side effect), so no context-keyed cache is needed for correctness, and none is added in C2: a cache is justified only by a measurement (pathological family ((F() * 0) * 0) … * 0 with an unknown F, quadratic in depth, bounded by the visit budget, measured in §8). C3 (merges and moves, several analyses per chain) is where a per-operation, reference-keyed memo inside the resource session becomes necessary; its key must then include the lexical scope (the canonicalization already knows it) and must not outlive the session.

The comparer keeps the default simplifier (ExpressionComparer.Default unchanged): the P9/P15 memos only store its results, so they need no policy key. A rule that compares under a relaxed policy uses the default comparer's equality, which is a sound (conservative) notion of equality for every policy.

7. Validation criteria

  • Default policy: the S5 campaigns (terminate, converge, diff, effects, s3, canon, 1,000 seeds, 1,000 nested) give byte-identical result files on master and on the branch (only environment.txt differs); the existing suites are unchanged.
  • Explicit policies: for every audited rule, positive and negative cases over the 32 policies; generated trees run compiled give the values, exceptions, traced effects and call counts the policy still guarantees (an evaluation dropped only when its permission holds; none added, repeated or moved in C2); no user call during simplification beyond the default's.
  • Security: custom reflection objects armed to throw are never read outside the gate; resource limits, stack guard and visit budget unchanged (256 KiB stack, deep trees, DAGs); derived simplifiers' own rules never run outside the gate.
  • Performance: A/A-controlled campaigns (default unchanged within the A/A spread; relaxed policies measured, with the pathological drop family).

8. Results

8.1 Stages C1 and C2 (this pull request)

Implemented as planned in §5.2, with the audited set of §3.1; contract in SimplificationPolicies.md §8.

Findings made while implementing, recorded here because they correct the audit:

  • The default already reduces F() + 0 to F(). The additive canonicalization of FinalizeExpression pins the non-inert term and drops the zero constant, even though the gate refuses the rules. So ExpressionComparer.Default already answers Equals(F() + 0, F()) = true; category A matters for the other identities (F() * 1, F() / 1, 0 - F(), F() ^ 1, …).
  • A clock read may be dropped under every non-default policy: B's table forbids repeating or moving a nondeterministic evaluation without aggressive simplification, never dropping it.
  • A throw is dropped only when its operand is analyzed: throw new E() holds a constructor (unknown code) and is never dropped; throw <constant> is MayThrowUserCode only.
  • The impersonating reflection objects are read by the framework when a call node is rebuilt (ContainsGenericParameters, Attributes, ReturnType, and GetHashCode/Equals of the framework's parameter cache), on the historical path too: L-1. The security test therefore checks that a relaxed policy reads no member the historical path does not read.

Second review follow-up (2026-11-09):

  • Detailed tracing matched skipped signatures. Once a node is outside the gate, an unaudited rule was skipped before its Match untraced, but matched under detailed tracing to report its rejection: tracing ran user code the untraced run does not (a custom ExpressionSignatureAttribute.Match can count, mutate or throw). The rule is now refused before Match at every level of tracing, the rejection still reported (DetailedTracing_MatchesNoSkippedSignature, which fails on the previous code).
  • The dropping identities called the public analysis entry. Analyze(t, ResourceLimits) opened a nested operation and validated t again for every attempted drop. The internal entry AnalyzeWithinOperation joins the running operation: the budgets are the same (the simplifier's limits are already those of the operation), the analysis visits stay counted (exact refusal one visit below), and a rebuilt or shared operand is still bounded by the structural budget and the stack guard (InternalAnalysis_JoinsTheRunningOperation). A rebuilt operand larger than the node limit is now refused by the structural budget rather than by the node limit.
  • Resource-limit tests moved to UtilsTest.Security: AuditedRuleAnalysis_UsesTheInstanceLimits and the budget-refusal part of OutsideGateFlag_IsScopedToTheAuditedRule (now ResourceRefusal_ClearsTheOutsideGateFlag).

Both code changes run only outside the gate, so the default path is unchanged. 8.2 Stage C2b (NaN fold under the policy)

Implemented as planned; contract, admitted operands and measurements in SimplificationPolicies.md §9. The default keeps the historical fold unchanged (FoldNaNOperandHistorical, no analysis call); every other policy, selected by UsesHistoricalAdmission, keeps the whitelist as its fast path and otherwise drops the operand when CanDiscard(AnalyzeWithinOperation(t, ResourceLimits), Options) allows it, at the three places the fold runs (the internal analysis entry of §8.1's second review follow-up; the public Analyze was used before it).

Findings made while implementing:

  • Nested refused folds were quadratic. Analyzing the dropped operand at every level re-analyzes the levels already refused. Monotonicity of CanDiscard over the flag union lets the fold refuse, without analysis, an operand that is or directly evaluates a NaN operation still present; a first version tested inertness first, and that uncounted walk cost +26 % at 100 levels: the NaN operation is now recognized first. The overhead left is a constant number of visits per tree, so no per-operation memo is introduced.
  • Two pre-existing superlinear families, met while measuring and identical on #686 and C2b under the same policy: S5A-14 (AdditionOfEqualsElements/FactorEqualityProbe, exponential on c + Abs(c + Abs(…)) with c ≠ 1) and S5A-15 (the power probe of MultiplicationOfEqualsElements, about n^3.8 on a Horner chain). They are left to P19d (§6), before C3. A non-default policy makes the NaN variant of S5A-14 linear, since every level folds.
  • The inertness walk is quadratic on inert nestings, but not worth a memo. On NaN + (NaN + (… x0) ^ 2) ^ 2 (harness family nanpow) the uncounted IsInertArithmetic walk examines 2n² + n nodes. A per-operation memo keyed by reference identity in the budget session made it linear (8,256 → 255 nodes at n = 64) with identical results, but gave no measurable gain (the comparer probes of S5A-14/15 cost 12.7 million structural visits on the same tree under every policy) and cost +5 % and +215 B on a two-node operand and +9 % on uncacheable operands; it was withdrawn (contract §9.7).
  • Repository invariant revised (review, 2026-11-09). Point 9 of Utils/AGENTS.md still required every dropped evaluation to be proven inert by ExpressionEffectAnalysis, which contradicts the explicit policies (NaN + (double)(10 / i) folds to NaN when arithmetic exceptions are not preserved). Adding an IsInert check before CanDiscard would void the policies, so the invariant now distinguishes the historical admission, the explicit-policy admission (audited rules, ExpressionBehaviorPermissions and the transformation's own conditions) and the guarantees common to every policy. Pinned by IntegralDivision_KeepsItsExceptionExactlyWhenPreserved (four forms, 32 policies, compiled at i = 0 and i = 5).
  • Reflection reads. C2b reads no member that #686 does not read under the same policy (180 sequences compared); the non-default policy's two extra node type reads on t / NaN are pre-existing, from the C1/C2 audited division rules.
