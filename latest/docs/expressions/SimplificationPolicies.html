All-purpose Utilities

Simplification policies — design note (S5 P18 Architecture B)

Status: public configuration (Architecture B), consumed by the zero and one identities since Architecture C, stages C1 and C2 (§8), and by the NaN fold since stage C2b (§9). The default policy gives exactly the historical results, user calls, exceptions and resource consumption; the canonicalization, the other rules, the comparer and the inlining do not consult the policy yet. Base of B: master f4bb85ec (after PR #682, A-10). Architecture C: audit and plan in ArchitectureC-Audit.md.

Related notes: BehaviorAnalysis.md (Architecture A: the classification and the permissions it prepared), A10-ReflectionProvenance.md (trust in reflection metadata).

1. API

namespace Utils.Expressions;

public enum ExpressionTrustPolicy { Verified = 0, TrustDeclarations = 1 }      // was internal (P18-A)

[Flags]
public enum ExpressionExceptionPreservation
{
    None = 0, Arithmetic = 1, Runtime = 2, UserCode = 4,
    All = Arithmetic | Runtime | UserCode,
}

public sealed record ExpressionSimplifierOptions
{
    public static ExpressionSimplifierOptions Default { get; }
    public ExpressionTrustPolicy TrustPolicy { get; init; }                        // Verified
    public bool AggressiveSimplification { get; init; }                            // false
    public ExpressionExceptionPreservation ExceptionPreservation { get; init; }    // All
}

// Utils.Mathematics.Expressions
public partial class ExpressionSimplifier
{
    public ExpressionSimplifierOptions Options { get; init; }                      // ExpressionSimplifierOptions.Default
}

Example:

var simplifier = new ExpressionSimplifier(ExpressionResourceLimits.Default)
{
    Options = new ExpressionSimplifierOptions
    {
        TrustPolicy = ExpressionTrustPolicy.TrustDeclarations,
        ExceptionPreservation = ExpressionExceptionPreservation.Runtime | ExpressionExceptionPreservation.UserCode,
    },
};

// Today: same result as new ExpressionSimplifier().Simplify(e).
Expression simplified = simplifier.Simplify(e);

Choices:

  • An init property, not a constructor. new ExpressionSimplifier(null) compiles today (to the limits overload); a one-argument options constructor would make it ambiguous, a source-breaking change. The property follows the existing SimplifyQuotedExpressions pattern, works with the limits constructor and on derived simplifiers, and needs no new constructor in subclasses. null is refused (ArgumentNullException).
  • The options hold the three policy axes only. Resource limits stay a constructor argument and SimplifyQuotedExpressions stays a property: both already have their own contract and are not rewrite permissions.
  • Immutable, validated record. The init accessors validate (ArgumentOutOfRangeException for an undefined trust policy or a flag outside All), so a with copy is validated too. Value equality makes policies comparable (a future memo key).
  • Frozen at construction. The simplifier keeps the reference it was given in a read-only field; there is no static, ambient or thread-local policy. Nested, re-entrant and concurrent calls on an instance apply the same policy; two instances never share one implicitly.
  • ExpressionTrustPolicy made public instead of a new enum: its two values and their meaning are those of P18-A and will not change in C.
  • Preservation flags rather than relaxation flags, as requested: All (preserve everything) is the default. Its zero value None is the least conservative one; the options default to All, so only an explicit choice reaches None.

2. The three axes

2.1 Declaration trust (TrustPolicy)

Verified (default) TrustDeclarations
[Deterministic] declaration treated as unknown code (Effective widens the flags to UnknownCode) trusted for what it promises: deterministic, no ambient state, no side effect
Exceptions of declared code – still MayThrowUserCode
Allocation, argument state – still Allocates / ReadsMutableState when the signature allows it
Undeclared, unverified code unknown unknown
Aggressive simplification not implied not implied

The audit of Effective found one non-conservative corner: it tested policy == Verified, so an undefined enum value reaching the internal permissions behaved as TrustDeclarations. It now tests policy != TrustDeclarations (any other value is verified). No current caller passes an undefined value; the public options refuse one.

2.2 Aggressive simplification (AggressiveSimplification)

Distinguish three things:

  1. No proof about an expression (Unknown, side effects, declarations not trusted): no policy makes it rewritable.
  2. A deliberately non-conservative transformation (this axis): the rewrite is correct for the value, but changes an identity or timing guarantee the conservative mode keeps.
  3. An incorrect transformation (introducing an exception, evaluating at simplification time, dropping a side effect, breaking the IEEE/domain contract): forbidden whatever the policy.

Relaxed by the axis (on analyzed code only):

  • Allocation identity and count: an evaluation that allocates may be dropped, merged, repeated or moved (two boxes may become one, an unused array may disappear).
  • Nondeterministic values without side effects: a clock read may be merged, repeated or moved (Now - Now may become 0), provided it raises no preserved exception category.

Kept, whatever its value: side effects; unknown code (it never becomes "verified", and nothing runs user code to find out); the preserved exception categories (only §2.3 decides them); declarations (only §2.1 decides them); the order of a mutable-state read relative to the side effects around it; the absence of introduced exceptions; no exception raised during simplification; the S3 symbolic contract (IEEE and domain-sensitive identities as today). Unknown expressions are unaffected.

2.3 Exception preservation (ExceptionPreservation)

A preserved category may not disappear nor be observed in another order. A category left out lifts one obstacle only: a future rule may, under its explicit conditions, drop the evaluation or move it among other movable evaluations. The other guarantees remain (side effects, allocation, determinism, mutable-state ordering, unknown code).

The five operations of the brief:

Operation Governed by Notes
1. Drop an exception (t * 0 -> 0 with a throwing t) the category (CanDiscard)
2. Change the order of two exceptions the category (CanReorder) each moved evaluation must be movable, and so must every evaluation it crosses (contextual)
3. Repeat an expression that may throw nothing for a deterministic one, locally it throws on its first evaluation either way; a nondeterministic one (aggressive only) must raise no preserved category; the position of the first evaluation must not move (else 2 applies, §3.6)
4. Merge several evaluations as 3, locally a merge that also moves the surviving occurrence, or that keeps a later occurrence instead of the first, is a reorder (2); §3.6
5. Move an exception from run time to simplification time never constant folding must not evaluate a throwing operation; not a policy dimension
(Introduce an exception) never

The three categories suffice: operations 1 and 2 are the only ones that change whether or when a category is observed, 3 and 4 reduce to them, and 5 is never allowed. A finer "operation kind" dimension (for example, allowing reordering but not dropping) has no demonstrated need; if C ever needs one, it would be a new, restrictive option whose default keeps today's meaning of a cleared category, so this API would not change meaning.

Unknown never becomes admissible by clearing categories: it always carries SideEffects and Unknown, which no policy lifts.

3. Permissions

ExpressionBehaviorPermissions (internal) answers, for one evaluation's ExpressionBehavior, under a policy: CanDiscard, CanRepeat, CanReorder. The P18-A overloads taking an ExpressionTrustPolicy remain and mean "the default policy with this trust"; the new overloads take an ExpressionSimplifierOptions. One private core per permission.

3.1 Table — which flag forbids which permission

Flag (after Effective) Discard Repeat / merge Reorder
SideEffects always always always
Unknown (with every flag) always always always
ReliesOnDeclaration under Verified always (widened to unknown) always always
Allocates unless aggressive unless aggressive unless aggressive
Nondeterministic never unless aggressive unless aggressive
MayThrowArithmetic if Arithmetic preserved only with Nondeterministic under aggressive, if preserved if Arithmetic preserved
MayThrowRuntime if Runtime preserved idem, Runtime if Runtime preserved
MayThrowUserCode if UserCode preserved idem, UserCode if UserCode preserved
ReadsMutableState never (local) never (local; contextual condition below) never (local; contextual condition below)

Under ExpressionSimplifierOptions.Default the table gives exactly the P18-A permissions (tested on all 512 flag combinations).

3.2 Priority rules

  1. Effective first: an untrusted declaration becomes unknown code.
  2. Imperative obstacles (SideEffects, Unknown) refuse every permission under every policy.
  3. Then each remaining flag is an obstacle unless the policy lifts it (allocation and nondeterminism by the aggressive axis, each exception flag by its category).

Every rule has the form "a flag forbids", so the permissions are monotone (tested over 512 behaviors × 32 policies): an extra flag never adds a permission; Verified is never more permissive than TrustDeclarations; preserving one more category never adds one; disabling aggressive simplification never adds one.

3.3 Local, not contextual

Reading mutable state is allowed by every permission. A permission says the evaluation itself may be dropped, repeated or moved; it does not say that its context allows it. Determinism is "same state, same outcome": CanRepeat on a[0] does not make a[0] + (a[0] = 1, 0) + a[0] mergeable. Before merging, repeating or moving an evaluation that reads mutable state, a rule must also prove that no evaluation with side effects, and no unknown code, runs between the occurrences or across the move, as SplitPinnedTerms does today. A move is allowed only among evaluations that are themselves movable. No policy relaxes this condition.

3.4 The ToEffects bridge

ToEffects(behavior, ExpressionTrustPolicy) is kept as it was: the gate's ExpressionEffects have no notion of nondeterminism or exception categories, so the bridge cannot express the aggressive and exception axes and stays as strict as the default there. A rule that honors those axes must ask the permissions with the options, not the bridged effects.

3.5 CanRepeat covers two different operations

CanRepeat is a local permission to change the number of evaluations (at least one remains). It covers two operations that are not interchangeable, and it is not a sufficient proof for either of them:

  • Merging several evaluations into one (t + t -> 2 * t): occurrences that could differ in the source now share one value. For a deterministic evaluation in an unchanged state they agree anyway; for a nondeterministic one (aggressive only), two clock reads become one snapshot.
  • Duplicating one evaluation (inlining an argument used twice): one value of the source becomes several evaluations. For a nondeterministic one, a value the source used consistently (c - c with c = Now, always 0) may now differ between its uses (Now - Now), a different and stronger change than a merge.

So C must check, for the exact transformation, the values (consistency of the uses of one evaluation, snapshot of several), the position of the surviving or added evaluations (§3.6) and the context (§3.3), instead of reading CanRepeat as "this rewrite is safe". A rule may impose a stricter condition than the permission (for example refuse to duplicate a nondeterministic evaluation even under aggressive simplification); it may never impose a weaker one.

3.6 Combined transformations

A transformation that combines dropping, merging, duplicating or moving must satisfy every permission corresponding to the modifications it actually makes, for each evaluation it affects, plus the contextual conditions of §3.3:

The transformation… Permissions required for the affected evaluation
drops it CanDiscard
changes its number of evaluations, the first one staying in place CanRepeat
changes its number of evaluations and moves the first (or keeps a later occurrence instead of the first) CanRepeat and CanReorder
moves it CanReorder, and every evaluation it crosses is movable
drops some occurrences and keeps others CanRepeat (count) and CanReorder if the kept one is not the first

Example: merging two deterministic evaluations that may throw is admissible locally (CanRepeat: the first one throws under the same conditions); a merge that also places the surviving evaluation after another one changes the order of exceptions and needs CanReorder, which a preserved category refuses. Likewise, an evaluation that reads mutable state may be merged only if no side effect separates the occurrences, whatever its permissions. Choosing a single permission (CanRepeat alone) for a combined rewrite is a defect of the rule, not a policy decision.

4. Guarantees of Architecture B (historical; see §8 for what C changed)

  • The simplifier stored the options and never read them: no rule, gate (AllowsRules), SplitPinnedTerms, CanonicalizesOperator, FinalizeExpression, comparer, canonical key, memo or inlining decision changed.
  • ExpressionComparer.Default and the comparer's internal simplifier are unchanged (default options). Still true after C.
  • No new analysis ran during simplification and no user code ran because of the options.
  • Resource consumption was identical (same transformation and structural visits; same refusals; same stack guard). Still true after C for the default policy.

5. Limitations

  • Only the zero and one identities (Architecture C, stages C1 and C2, §8) and the NaN fold (stage C2b, §9) consume the options; the canonicalization, the factoring and merging rules and the inlining do not yet.
  • ExpressionComparer always simplifies with the default policy (its internal instance is not configurable).
  • The permissions inherit the P18-A classification and its known gaps: the Pow omission (conservative; fixed since), and the A10-B, A10-C, L-1, L-2 findings (see the A-10 note).
  • TrustDeclarations trusts the author: a lying declaration ([Deterministic] on a counter) would be merged under C. This is the documented purpose of the axis, and the reason it is off by default.

Problems to solve before activation (status after C2 in bold):

  1. Per-rule effect declarations. The gate is coarse (operands inert or not). Each rule must declare which evaluations it drops, merges or moves, so the right permission is asked; otherwise a relaxed policy over-applies. Solved by audited rules that check their own permissions (§8); only the zero and one identities are audited.
  2. Cost. ExpressionBehaviorAnalysis costs about 40 ns plus 12–25 ns per node per call; asking it at every rule on every node would be quadratic. C needs a per-operation, reference-keyed behavior memo inside the resource session (and the visit budget must count it).
  3. Policy-keyed caches. The comparison memos (S5 P9, P15), the factor cache (P3) and the comparer's simplification must be keyed by policy, or kept on the default; a nested simplification with another policy joins the running session today. The value equality of ExpressionSimplifierOptions makes it usable in a key, but it is not a sufficient key: every cache must also include whatever else influences its result — the lexical scope context (bound parameters, binder frames), the resource session it lives in (entries must not outlive or cross sessions), and the simplifier instance or runtime type when a derived simplifier or SimplifyQuotedExpressions changes the rules.
  4. Contextual ordering. The local permissions must be combined with a proof that no side effect or unknown code runs between merged occurrences or across a move (§3.3); SplitPinnedTerms is the model.
  5. Correctness items first. P18b (S5A-03, S5A-13: decimal division exceptions) and the Pow omission change what is classified as throwing; A10-B must be fixed before any policy widens comparisons of nodes holding reflection objects. P18b and Pow are separate pull requests (#684, #685), not prerequisites of C2 (the audit, §4, explains why); A10-B is avoided by invariant I-1 (permissions before any comparison) rather than fixed.
  6. Contract decision. Enabling any axis changes results and user-call counts; C needs its own compatibility entry (as C-05 and C-06 had). Decided on 2026-11-05: the default stays strictly historical; the conservative improvements of the default go to a separate pull request with the compatibility entry C-08 (§8).

8. Architecture C, stages C1 and C2 — the zero and one identities consume the policy

Audit, decisions and plan: ArchitectureC-Audit.md.

8.1 Admission

  • Historical admission (unchanged). A node's rules run when its operands are inert (AllowsRules, ETC R1b, C-06).
  • Default policy: historical admission alone. ExpressionSimplifier.UsesHistoricalAdmission is true when Options equals ExpressionSimplifierOptions.Default by value: results, user calls, exceptions and resource consumption are those of master before C (the S5 campaigns give byte-identical files), and so are the answers of ExpressionComparer.Default.
  • Any other policy: audited rules outside the gate. When the gate refuses a node, the dispatch (ExpressionTransformer.TryTransform) asks AllowsAuditedRulesOutsideGate once; if it allows, only the rules IsAuditedRule lists run, each with the thread-static flag RuleRunsOutsideGate set for its call (and the rules it calls directly), cleared for every node transformed meanwhile (TransformPrepared), restored on failure. Every other candidate is traced as rejected by the effect gate.
  • Audited rules. The ten overloads of AdditionWithZero, SubstractionWithZero, MultiplicationWithZeroOrOne, DivideWithZeroOrOne, DivideWithZero, PowerOfZeroOrOne and PowerByZeroOrOne declared by ExpressionSimplifier, identified by method handle: a derived simplifier's own rules, even one hiding an audited rule with new, keep the historical admission.

Leaving the historical mode is not a relaxation of an axis: any non-default policy, whatever its axes, also enables the rewrites that change no evaluation (category A of the audit), because they are correct under every policy. Each axis still relaxes only its own flags of the permission table (§3.1).

8.4 Guarantees kept under every policy

No side effect or unknown code is dropped; no exception is added, and none is moved to simplification time; an exception disappears only with a dropped evaluation of a category the policy does not preserve; no evaluation is duplicated, merged or moved by C2; no user code runs because of the policy (the dropped operand is analyzed, never evaluated; a custom reflection object is unknown code, read no more than by the historical path); the resource limits, the visit budgets and the stack guard apply to the analysis.

No measurable cost: every difference is within −5.5 % to +1.8 %, the A/A control within −4.8 % to +4.0 %, the allocations are identical to the byte (a few bytes of rounding on the largest cases), and the shared DAG, which looked like the largest regression in the unpinned campaigns, is +0.8 % against an A/A of +0.3 % over 6 rounds. Relaxed policy. A node refused by the gate where an audited rule applies costs about 0.25–0.55 µs more and up to 400 bytes: the audited rules run (with their reflection invocation), a refused drop runs the behavior analysis (at the time of this measurement a validation and a walk of the operand; the walk alone since the internal entry of §8.2), and F(x) + 0 re-transforms its operand (AdditionWithZero returns TransformCore(left), finding S5A-07) where the default reduces it by the canonicalization alone. When the rewrite shortens the tree (F(x) * 1), the simplification is faster and allocates less. The pathological nesting of products by zero stays at +0.2 % in time and +2.2 % in allocations at 100 levels: its quadratic structural work (see the security test) is small next to the transformation work.

9. Architecture C, stage C2b — the NaN fold consumes the policy

9.1 Two paths

IEEE-754 makes +, -, * and / return NaN when an operand is NaN, so t + NaN -> NaN is numerically exact whatever t is; the only question is whether the evaluation of t may be dropped. The fold (S5 P11b) runs after the rules of every prepared node, at the three places it always ran: the root of an operation (TransformWithinBoundary), every prepared node (PrepareExpression) and every lambda body (RebuildLambdaExpression, so a body that is not prepared on its own is folded too).

  • Historical path, the default policy's only one (FoldNaNOperandHistorical, the former FoldNaNOperand unchanged): t is dropped only when the static whitelist IsEliminableFloatingOperand proves it is made of constants, parameters, ordinary negations and ordinary IEEE + - * / of double/float. No behavior analysis runs, so results, visits and allocations are those of PR #686 (the S5 campaigns are byte-identical).
  • Policy path, every other policy (FoldNaNOperandWithPolicy), chosen by UsesHistoricalAdmission of the instance, never by the thread-static RuleRunsOutsideGate (the fold runs in whatever rule context prepared the node, and a nested simplification by another instance applies its own policy). Its checks, from the cheapest:
    1. the historical recognition, unchanged: a NaN operand (TryGetNaNOperand: the constant, its ordinary negation, c - NaN), one of the four operators, IsOrdinaryBinaryArithmetic (no custom, lifted, nullable or checked operator, no Power);
    2. the whitelist: accepted operands are dropped without analysis. This fast path is sound under every policy: what it accepts has no behavior flag at all (a parameter read, a constant, IEEE arithmetic that cannot throw), and CanDiscard only tests for flags;
    3. an operand that is itself a NaN operation (IsNaNOperation) is kept: inert, it keeps the historical decision of step 4; otherwise its own fold was refused (§9.5). Testing it first spares the inert walk of step 4, which would descend every level of NaN + (NaN * (… F()));
    4. inert arithmetic (IsInertArithmetic, such as x ^ y) keeps the historical decision, so that the S5 P16 reuse of the comparer's simplified forms (EqualsKeepingSimplifiedForms), which assumes that preparing an inert operand again builds the default's tree, stays valid;
    5. an operand that directly evaluates a NaN node the policy left unfolded is refused without analysis (HoldsRefusedNaNFold, §9.5);
    6. otherwise t, and t alone, is analyzed: ExpressionBehaviorPermissions.CanDiscard(ExpressionBehaviorAnalysis.AnalyzeWithinOperation(t, ResourceLimits), Options), the internal entry that joins the running operation without validating t again (§8.2).

The fold drops one evaluation and does nothing else: it merges, duplicates and moves nothing, so CanDiscard is the only permission involved, and the NaN constant returned is the operand's own (its payload and type are kept).

9.3 Guarantees kept under every policy

Only float and double and the four operators fold; a custom, lifted, nullable or checked operator and Power never do. No side effect, unknown code, opaque node or custom reflection object is dropped; an exception disappears only with a dropped evaluation whose category the policy does not preserve; an allocation only under aggressive simplification; nothing is added, repeated or moved. The analysis never runs the analyzed tree, reads no member of an opaque node (it is classified by its class) and none of a custom reflection object (§9.4); it joins the running operation under the instance's limits, so its visits count in MaxStructuralVisits and its recursion in the stack guard. A disabled quote stays a strict boundary.

9.4 Reflection reads

On the same trees and policies (default, aggressive, trust, no exception preserved, permissive; exact and derived simplifiers; nine NaN shapes around an impersonation of Math.Sin and around a recording extension node, including nested refusals and a lambda body), PR #686 and C2b read exactly the same members, in the same order, with the same outcomes (180 sequences compared): C2b introduces no reflection read. The reads that a non-default policy adds over the default are pre-existing, from C1/C2: on t / NaN only, two more node type reads (ReturnType of the impersonating method, Type of the extension node), because the audited zero/one rules rebuild the division; the other members read are the same (L-1 of the A-10 note).

9.5 Nested refusals

Without steps 3 and 5, a nesting of refused folds analyzes at every level the whole operand below it, that is the levels already refused: NaN + (NaN * (NaN + … F())) added n² + n structural visits (65,792 at n = 256, on top of the 96,649 of the default), and NaN + S * (NaN + S * (… F())), linear under the default, became quadratic (+657,920 at n = 256). Steps 3 and 5 rely on monotonicity: the behavior of an ordinary method-less IEEE operation is the union of its operands' flags, and CanDiscard only tests the absence of flags, so an operand that is, or directly evaluates, a refused NaN node cannot be discarded either. A NaN node still present, fully simplified and not inert has been through the policy path of this instance and was refused (or a node it directly evaluates was, by induction). A NaN node rebuilt after its own preparation has not been through the fold: the shortcut may then keep a fold the analysis would allow, a missed simplification, never an unsound one (the S5 campaigns under the permissive policy, 1,000 seeds, give byte-identical results with and without the shortcut; the unit test NestedRefusal_DecidesAsTheAnalysis checks the decision against the analysis on every family and policy). With it, both nestings cost the default's visits plus one analysis of the bottom level (+2 and +20 structural visits at every depth).

9.6 Measurements

PR #686 (30046b86, "base") and C2b were built side by side and measured under strictly identical configurations: same trees, same policies (the default, and the permissive policy TrustDeclarations + AggressiveSimplification + no exception preserved; the aggressive policy gives the same counts as the permissive one on these families), one process per variant pinned to two performance cores (affinity 0x14, high priority). Visits are the engine's counters (TransformVisits, StructuralVisits) and are deterministic; times are medians of a growth probe, indicative only. The families:

  • A: ((x*y + 1)*y + 1)…, Horner, no NaN;
  • B: NaN + Abs(NaN + Abs(… Sin(x)));
  • C: NaN + (NaN * (NaN + (… F(x)))), nested refused folds;
  • D: NaN + S * (NaN + S * (… F(x))), with S a shared chain of 16 Sin/Cos;
  • E: NaN + { v = x; v = Sin(v) * 2; … ; v }, a block of n statements.

Historical anomalies (pre-existing on #686, outside C2b). Family A grows as about n^3.8 under every policy, identically on both builds (the power-combination probe of MultiplicationOfEqualsElements, finding S5A-15). Family B is exponential under the default (AdditionOfEqualsElements and FactorEqualityProbe compare a constant other than 1 with the call at every level, 2^(n+2) − 4 comparer simplifications, finding S5A-14), identically on both builds. Family C is already quadratic in structural visits under the default (the comparer probes of each level walk the levels below). Their correction (P19d of the S5 tracking) is not part of C2b. P19d (2026-11-10) fixed A and B by retaining the comparison memo across the comparison sessions of one operation (ArchitectureC-Audit.md §8.3): Horner at n = 64 takes 8,388 visits and is accepted by the default limits, constabs grows quadratically. When both versions complete, the results are the same; the reduced work can let an operation that the resource limits refused before complete now.

9.7 Per-operation memo of the inert classification (studied, not kept)

Step 3 of §9.1 tests IsInertArithmetic on the operand at every level, and that walk is not counted in the visits. On a nesting whose operand is inert arithmetic at every level, the harness family nanpow, NaN + (NaN + (… x0) ^ 2) ^ 2, every level walks the whole operand again: the walk examines 2n² + n nodes (136, 528, 2,080, 8,256 at n = 8, 16, 32, 64), a quadratic term. A memo of the classification was implemented and measured on ecfacda4, then withdrawn; the patch is not kept in the repository.

What was built. A table Dictionary<Expression, bool> keyed by reference identity (ReferenceEqualityComparer.Instance, never ExpressionComparer nor the nodes' or constants' Equals), held by the thread's ExpressionResourceBudget session, created on the first classification and dropped when the outermost operation exits. Only IsInertArithmetic was memoized, through a new cached entry point used by FoldNaNOperandWithPolicy and HoldsRefusedNaNFold; the historical walk kept its callers. It stored every intermediate node and the negative results. Every examined node consumed one structural visit (none on a table hit). A node was stored only when its classification read no metadata that user code can supply: a node type that is not a runtime type (TypeDelegator, L-2), a user MethodInfo (A10-B), or an operand whose Type is not stored (IsLifted reads Left.Type, L-1) left its result uncached, never turned into false.
