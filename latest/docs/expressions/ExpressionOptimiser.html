ExpressionOptimiser — safety audit and contract (A10-C, O0–O5)

Branch fix/expression-optimiser-safety, base master 76bf0b55 (PRs #715, #716 and #717 merged). This document records the audit of the public Utils.Expressions.ExpressionOptimiser, the defects found, the rules kept with their guards, and the limits of the optimiser. It closes finding A10-C of A10-ReflectionProvenance.md and the correctness part of the execution-optimizer stage O0 of Utils/TODO-2026-09-12-expression-simplifier-roadmap.md.

Vocabulary: proven defect (a reproducer fails on 76bf0b55), confirmed risk (the mechanism exists, no reproducer), deliberate limitation, changed behavior (to keep the semantics), optimisation not made.

1. Consumers and compatibility

ExpressionOptimiser has no consumer inside the repository: no project calls Optimize (verified with a search of every project, generators and packaged-acceptance consumers included). Its consumers are external users of omy.Utils, documented by Utils/README.md. The public surface keeps the parameterless constructor and Optimize(Expression); the only additions are ExpressionOptimiser(ExpressionResourceLimits) and ResourceLimits, the convention of ExpressionSimplifier and ExpressionComparer. Behavioral changes visible to a consumer:

Change Before After
Identities that were not exact applied (x * 0 -> 0 dropped F(), x + 0.0 -> x changed -0.0, …) declined (§3)
Type of a rewritten node could change (Block(7, Empty()) became int) always the source type
Extension and dynamic nodes Accept/VisitChildren/Reduce called; dynamic reduced to a call site passed through / kept, never called
Quoted expressions rewritten inside kept as data
Resource limits none (stack overflow on deep input) ExpressionResourceLimits.Default: depth 512, 50,000 logical nodes, 10,000,000 structural visits, stack guard

A consumer optimising trusted trees deeper than 512 levels or larger than 50,000 logical nodes passes ExpressionResourceLimits.Unlimited (the stack guard stays active).

2. O0 — architecture of the audited version (76bf0b55)

A private ExpressionVisitor (StandardOptimiserVisitor) with five overrides: VisitUnary, VisitBinary, VisitConditional, VisitBlock, plus the framework defaults for every other family. Findings on the traversal itself:

  • Families. Every framework family is visited by ExpressionVisitor, including quoted lambdas (rewritten as data) and DynamicExpression: a plain visitor reaches it through VisitExtension, whose default calls VisitChildren, hence Reduce, which replaces the operation by CallSite<T>.Target(site, …) (proven defect D-12).
  • Extension nodes. Visit calls the node's overridable Accept, then VisitChildren, CanReduce and Reduce (proven defect D-11, ETC R4).
  • Resources. No validation, no budget, no stack guard: a deep tree overflows the stack and kills the process (confirmed risk R-1: not reproducible in-process, the test host dies), and the framework's binding walk recurses through nested member bindings with a delegate per level.
  • DAGs. A shared subtree is walked once per use (unfolded), and a rewritten one is rebuilt once per use.
  • Scopes. Variables and labels are never renamed; the only scope hazard is the block unwrapping of D-9/D-10.
  • Exceptions. The optimiser runs no user code except through D-11; CreateZeroConstant (Convert.ChangeType) throws InvalidCastException on an enumeration type (proven defect D-6).

5. Confirmed risks without in-process reproducer, and deliberate limitations

  • R-1 stack overflow on 76bf0b55 for deep inputs (unary, binary, nested bindings): kills the process, so no in-process test can fail on master; the branch tests (HostileNesting_OfEveryFamily_IsRefusedOnASmallStack) end every family with a controlled Stack refusal on a 256 KiB thread.
  • Signaling NaN. x * 1.0, x / 1.0, x + (-0.0), x - 0.0 return x itself; the source operation may quiet a signaling NaN (quiet bit set). Quiet NaN payloads are kept (tested with 0x7FF8000000000123). Signaling NaNs are outside the contract, as for C compilers without -fsignaling-nans.
  • Framework reads of hostile reflection objects on rebuild. When a child of a call, member, binding or initializer changes, the framework factory (Update) revalidates the parent and reads its reflection object (as for every engine rebuild, documented in ExpressionOpacity). The optimiser itself never reads one: operator methods are only compared with null, and an unchanged node is never rebuilt (ImpersonatingMember_InAnUnchangedInitialization_IsNeverRead).
  • Implicitly typed conditional chains. ConditionalExpression.Type delegates to IfTrue.Type; a chain nested through IfTrue costs O(depth) per read in the framework (its construction is already quadratic). The optimiser reads it once per conditional with a constant test, after the opacity check of both branches.
  • DAGs are walked per logical node, like every engine walk: bounded by MaxNodes (validated without unfolding) and by the structural budget, which also counts the effect analysis (SharedDag_IsBoundedByTheLimits, SharedProductsByZero_AreBoundedByTheBudget). Memoising rewrites by reference would make DAGs linear but costs a table on every call; not done.
  • No fixed point. One bottom-up pass: rewrites whose result enables a rule higher up are applied ((x * 1 + 0) * (x - 0) → x * x); a rule enabled only by a later sibling is not revisited.

Guard mutation check

Each guard was disabled in turn and the optimiser tests rerun (Debug): the label, discardability, operator-method, signed-zero, operand-opacity, lifted-product, quote, conditional-type, label-unwrap and dynamic-rebuild guards each make 1 to 5 tests fail. The inner-negation method guard survived the first run (no test had a primitive outer negation over a custom inner one); the case was added. The "keep the last block expression" guard is an equivalent mutant: dropping a final Default(void) and rebuilding through BlockExpression.Update, which keeps the block's type, gives the same type and behavior; the guard is kept for structural fidelity.

6. Architecture

A — keep the ExpressionVisitor, add guards (retained). Visit counts one structural visit (stack check included) and returns an extension node before Accept; VisitExtension rebuilds a dynamic operation from its arguments; VisitUnary keeps quotes; VisitMemberInit/VisitListInit walk bindings and initializers with the optimiser's own loop (one visit per binding and initializer, original AddMethod), so the framework's delegate-per-level binding recursion never runs; VisitCatchBlock and VisitSwitchCase count their container. Optimize runs inside ExpressionResourceBudget.Run (input validation, budgets, Stack translation at the outermost boundary, finally restoration, nested calls join and only tighten). Rule admission is centralised in TryGetArithmeticKind, Classify, KeepIfNeutral and the Method is null / IsOpaque / exact-type checks; discardability reuses ExpressionEffectAnalysis. About 600 lines, no new public concept.

B — rebuild on ExpressionTransformer (not retained). Benefits: budgets, validation, rebuilds, scopes and opacity conventions already tested. Costs measured or established during the audit: every node goes through TransformCore (preparation, plan dispatch, CopyExpression finalisation), which costs about 1–4 µs per visit against 50–250 ns per node for the visitor (§8); the transformer's rules are dispatched by signature, which would make the short-circuit, conditional and block rules (that must not visit a discarded child) awkward; and the transformer copies node families the optimiser leaves untouched, changing rebuild counts. A gives every invariant with the existing session, so B brings no correctness benefit.

Structural visits on the branch, measured as the smallest accepted MaxStructuralVisits: logical nodes + 1 (the lambda's parameter) on every workload, the effect analysis of the small operands of x * 0 being answered by its shallow path without counting.

Explanation: the added cost is per node, about 15–20 ns (ConsumeStructuralVisit: stack check and thread-static counter, then the opacity type tests), plus the shape validation (about 30 % of the overhead, an unfolded walk of the input), plus a fixed ≈ 0.5 µs per call for the session. Constant conditionals also pay the label search of their discarded branch. arithmetic is faster although its output is identical: the exact constant classification is a type switch on the boxed value, where master called Convert.ToDouble up to four times per arithmetic node. Allocations never grow except for the reused label finder (24 B per call with a constant conditional); unchanged blocks no longer allocate. The overhead is the price of the controlled refusals and of R4, of the same order as the other engine walks; no optimisation of the rules was attempted beyond removing two allocations.

9. Tracing

Optimize bypasses TransformCore, so it opens its own treatments of the active trace (Utils/AGENTS.md rule 13). Inside a tracing scope, Optimize builds a TracedOptimiserVisitor. Each node visited (after its structural visit is counted) is one treatment reported for ExpressionOptimiser. It produces TransformEnter, then RuleApplied when a rule rewrote the node, then TransformExit. A failure is reported as TransformFailed from an exception filter that only records; the resource refusal is reported once, as ResourceLimitReached. The rule is identified by the method implementing it (RewriteAdd, RewriteSubtract, RewriteMultiply, RewriteDivide, RewriteConvert, RewriteNegate, VisitShortCircuit, VisitConditional, VisitBlock for removed empty statements, UnwrapBlock). The RuleApplied input is the source node: the rules read the visited children directly, without a prepared copy.

Exit outcomes are Unchanged, Rebuilt (a node rebuilt around rewritten children), RuleApplied, or Boundary for a quote. An extension node is a treatment without node type and is never read. The detailed level adds no event, because the optimiser has no candidate rules and no lexical scopes. The input validation refuses before any visit, so its refusal is a single ResourceLimitReached event without treatment. An optimisation nested in a traced operation joins that operation's trace.

The untraced visitor holds no tracing state: a call pays one field read when it starts, and each rewrite pays one virtual call. Campaign tests/ExpressionTracingBench (opt-* scenarios, baseline cf920869, A/A control, 3 to 7 rounds):
