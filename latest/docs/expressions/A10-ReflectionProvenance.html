S5 A-10 — Trust in reflection metadata (fix note)

Base: master 623c7802 (after PR #681). Scope: the expression engine must never give the privileges of an intrinsic or trusted member to a reflection object that is not the runtime's own, and its decisions must never run the members of such an object. This is not a general protection against user code: user methods obtained through ordinary reflection stay user code, analyzed as before.

1. Root cause

System.Linq.Expressions factories accept any subclass of MethodInfo, FieldInfo, PropertyInfo and ConstructorInfo. Every member of such a subclass is user code: DeclaringType, Name, Attributes, GetParameters, ReturnType, IsDefined, Equals, GetHashCode. Several engine decisions read that metadata, or compared it with == (which calls the left operand's Equals), to decide that a node was intrinsic or inert:

  • the effect gate's method classification and its ConcurrentDictionary<MethodInfo, …> cache (hash and equality first, then DeclaringType == typeof(Math) and the name);
  • the "ordinary arithmetic" checks (IsOrdinaryBinaryArithmetic, IsOrdinaryUnaryNegate), which compared the node's operator method with the expected one through the node method's own Equals;
  • the call-rule signatures (ExpressionCallSignatureAttribute.Match), which matched rules on DeclaringType and Name, and whose rules replace the call by an intrinsic node or by the real function;
  • the gate's operator and conversion classification (DeclaringType == typeof(decimal), Name == "op_Implicit") and its field classification (IsInitOnly, IsLiteral, read from the user's Attributes);
  • the inlining analysis (GetParameters for by-reference arguments, IsDefined(IsReadOnlyAttribute) for receiver mutation).

3. Fix

One provenance check, ExpressionReflectionProvenance (internal, Utils/Expressions/ExpressionReflectionProvenance.cs):

  • IsRuntime(member) compares member.GetType() (not virtual) by reference with the closed set of concrete classes the runtime uses for loaded code: methods (RuntimeMethodInfo: ordinary, generic definitions and instantiations, array methods, methods of created dynamic and collectible types), constructors, ordinary and literal fields, properties, and DynamicMethod. The classes are read at type initialization from members of object, string and int, never named.
  • IsSameMember(actual, expected) compares a node's member with an expected runtime member without calling the equality of an object that is not a runtime one.

Applied at every decision point found by the audit (§4), always before any member of the object is read and before it reaches a cache:

Site Change
ExpressionEffectAnalysis.MethodEffects and its cache non-runtime method: Observable, never cached
ExpressionEffectAnalysis.OperatorMethodEffects non-runtime operator method: Observable
ExpressionEffectAnalysis.ConversionEffects non-runtime conversion method: Observable
ExpressionEffectAnalysis.AnalyzeMember non-runtime field: Observable
ExpressionSimplifier.IsOrdinaryBinaryArithmetic, IsOrdinaryUnaryNegate (hence IsOrdinaryFieldDivision) non-runtime method refused before IsLifted; comparison through IsSameMember
ExpressionCallSignatureAttribute.Match non-runtime method never matches a call rule
AdditionOfCos2andSin2Number, CanCombineUnaryLogCalls comparison through IsSameMember (defense in depth)
InvocationInliningAnalysis (ScanCall, ScanMember, ScanNew, ScanIndex) non-runtime member: Preserve
ExpressionMethodBehaviors, ExpressionBehaviorAnalysis (P18-A) same check (previously "declared in the core library", which also accepted emit builders)
ExpressionTraceFormatter renders <custom member> instead of reading the name

No public API change. ExpressionCallSignatureAttribute.Match (public) no longer matches a call whose method is not a runtime reflection object; nothing else changes for runtime objects. Declarations ([Deterministic]) are still not consumed, and the exception policy is unchanged.

Why 17–19 are not bypasses of the fix: the simplifier compares, hashes, memoizes or keys only operands that passed the gate (AllowsRules) or terms that were not pinned (SplitPinnedTerms); after the fix any node holding a non-runtime reflection object is observable, so these consumers never decide a rewrite of such a node.

5. Distinct findings (not fixed here)

  • A10-B — structural consumers call the members of custom reflection objects. ExpressionComparer.Equals(fake, real) returns true while Equals(real, fake) returns false (asymmetric), both hash alike, and the comparison calls the fake's Attributes, GetHashCode, GetParameters, DeclaringType, Equals and ReturnType. Same pattern in the canonical keys and the comparison memos. Proposed fix (separate PR): compare and hash non-runtime reflection objects by reference identity, never through their members.
  • A10-C — ExpressionOptimiser drops evaluations. The separate ExpressionOptimiser rewrites x * 0 -> 0, x + 0 -> x and x * 1 -> x without any effect or operator check: F() * 0 loses the call of F, and a custom operator is treated as arithmetic. Unrelated to reflection provenance; proposed as a separate PR.
  • P18-A list omission. Pow was missing from the total floating functions of ExpressionMethodBehaviors (the gate trusts it). Conservative (UnknownCode); fixed by the S5 P18 Pow classification change (see BehaviorAnalysis.md §5).

6. Tests

  • UtilsTest.Security/Expressions/ExpressionReflectionProvenanceTests (8 tests; 7 fail on master): S-01/S-08 impersonated Math.Sin, double.Sin, Math.Pow keep every evaluation (counted through the expression interpreter, which calls the fake's Invoke) for the exact and a derived simplifier; S-02/S-10 with every member armed to throw, the provenance check, the gate, the ordinary-arithmetic checks, the call signatures, the inlining analysis and the public analysis read nothing; S-06 caches, sequential and concurrent, with hash-sharing impersonations; S-03 operators; S-04 conversions; S-05 fields and properties; provenance classes (ordinary, generic, array, dynamic, collectible, DynamicMethod, constructors, literal fields, properties accepted; emit builders, user subclasses, null refused); S-09 hostile nestings and DAGs refused by the resource limits without any member read.
  • UtilsTest/Mathematics/Expressions/Coverage/ExpressionReflectionProvenanceControlTests (category S5-A10, S-07): real Math.Sin, MathF.Sin, double.Sin, float.Sin, Math.Pow, decimal operators, conversions and fields keep their classification and simplifications.

7. Residual limitations

  • L-1 — framework getters delegate to the object. MethodCallExpression.Type returns Method.ReturnType; BinaryExpression.IsLifted and UnaryExpression.IsLifted read GetParameters for nullable operands; the framework factories that rebuild a parent read the members they validate. Every engine walk reads node types, so a custom method's ReturnType still runs during simplification (the tests count these reads instead of refusing them). These reads cannot grant any trust; making such nodes fully opaque would mean treating every node that holds a custom reflection object like an extension node in every walk.
  • L-2 — Type provenance. The factories accept TypeDelegator and user Type subclasses as node types. The gate's conversion rules read IsPrimitive, IsValueType and IsEnum of node types. Out of the scope of this fix (method, member, operator and conversion metadata); to study separately.
  • Emit builders (MethodBuilder before CreateType, generic instantiations over type builders) are refused conservatively.

Simplify on the 11-case corpus: −2.0 % to +4.5 %, inside the A/A spread of the same campaign (up to ±19 % on the smallest cases, ±1–4 % on the larger ones).
