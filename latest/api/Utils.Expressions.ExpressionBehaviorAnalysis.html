Classifies what evaluating an expression tree may do besides producing its value: whether it is deterministic, reads mutable state, has side effects, allocates, and which kinds of exceptions it may throw, with the parts of the classification that could not be analyzed or that rely on user declarations (S5 P18 Architecture A).

Remarks

Read-only foundation. The analysis never changes a tree, never compiles, evaluates or invokes anything, and is not consulted by ExpressionSimplifier or ExpressionComparer: their results and the user calls they make are those of the strict internal effect gate of ETC R1b. This classification is finer (exception origins, determinism, declarations, lambda bodies) and is meant to back future, explicitly enabled simplification policies.

Calls and expressions. AnalyzeMethod(MethodInfo) classifies the execution of a method alone, its arguments already evaluated. Analyze(Expression) classifies an expression: a call is the union of the method's own behavior, of its receiver and of its arguments, plus a possible null receiver; a deterministic method called with a free parameter is a deterministic expression that reads mutable state.

Scopes. A parameter or variable that is free in the analyzed tree is mutable state (its value is supplied, and may be changed, by the enclosing code). A variable declared inside the tree (a block variable, the parameter of an invoked lambda, and for AnalyzeInvocation(LambdaExpression) the parameters of the analyzed lambda) is local: reading it reads no outside state and writing it is not a side effect, unless a closure or a quoted tree that escapes the evaluation captures it, or it is passed by reference.

Lambdas. Evaluating a lambda only allocates a delegate: its body is not part of that evaluation, so its behavior is Allocates whatever the body does. A lambda invoked in place (Invoke(lambda, args)) and the conversion lambda of a coalescing or compound assignment run their body, which is analyzed recursively with its parameters bound. AnalyzeInvocation(LambdaExpression) classifies one invocation of a lambda. Any other delegate invocation is unknown code.

Unknown code. Unannotated user methods, property getters and setters outside the trusted lists, constructors, custom operators and conversions without a declaration, delegate invocations, loops, jumps, labels, switches, try blocks, member and list initializers, runtime variables, debug information, dynamic operations and extension nodes are UnknownCode. An extension node is recognized by its class only (IsOpaque(Expression)): none of its members is read, nor the Type or NodeType of a node that may be one. A dynamic operation's binder is never invoked. A reflection object that is not a runtime one (a user subclass of MethodInfo, FieldInfo or PropertyInfo) is unknown code without any member read.

Not modeled. Asynchronous and resource exceptions (OutOfMemoryException, a stack overflow, a thread abort), the evaluation time, and whether the evaluation terminates.

Resources. Each call is one expression operation (ExpressionResourceLimits): the input is validated against the depth and node limits first, each analyzed node counts one structural visit and checks the execution stack, and a call made while another operation runs on the thread joins it and can only tighten its limits. The analysis keeps its state in a per-call object and in thread-safe caches of method metadata, so concurrent calls are independent.
