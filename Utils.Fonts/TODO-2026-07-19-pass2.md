# Utils.Fonts — Second quality and security audit pass (2026-07-19)

Follow-up static audit of the current `Utils.Fonts` package after the completed functional fixes and remaining debt recorded in `DONE-2026-07-10.md`. This pass focuses on hostile-font parsing, table-directory invariants, `loca`/`glyf` correctness, cmap state exposure, composite glyph limits, resource ownership, and package stability. No production code is changed.

## Critical and high-priority findings

### 21. Short-format `loca` entries are parsed as signed values

`LocaTable.ReadData` reads short-format offsets through `ReadArray<short>` and shifts each signed value left by one. The OpenType field is `Offset16`, an unsigned 16-bit value divided by two. Encoded values from `0x8000` through `0xFFFF` therefore become negative offsets.

**Risk:** valid large fonts can resolve glyphs before the beginning of `glyf`; malformed fonts can create negative sizes and incidental seek/range failures.

**Fix:** read and write `UInt16`, widen before multiplying by two, and validate monotonicity plus the final offset against the `glyf` table length.

**Priority: P0 binary correctness and hostile-input safety.**

### 22. Short-format `loca` serialization silently truncates invalid offsets

Writing uses `(short)(offset >> 1)` without checking that offsets are non-negative, even, monotonic, or representable in short `loca` format. Odd glyph boundaries lose one byte and offsets above `0x1FFFE` wrap.

**Fix:** validate every offset before writing; automatically switch `head.indexToLocFormat` to long format when necessary, or reject the font with a contextual exception.

**Priority: P0 font corruption.**

### 23. The SFNT directory treats unsigned fields as signed and does not validate table bounds

`numTables` is read as `Int16`; table checksums, offsets, and lengths are read as signed `Int32`. Negative counts, offsets, or lengths are not rejected. Nor is `offset + length` checked with overflow-safe arithmetic against the source length before seeking and allocating.

**Risk:** malformed input can trigger negative allocations, arbitrary seeks, overflow, excessive memory use, or confusing lower-level exceptions.

**Fix:** parse specification-defined unsigned fields as `UInt16`/`UInt32`, apply explicit implementation limits, use checked 64-bit range calculations, and require every table range to fit completely in the font.

**Priority: P0 parser boundary validation.**

### 24. Duplicate directory offsets are silently discarded

Directory records are stored in a `SortedSet<TableDeclaration>`, while `CompareTo` compares only `Offset`. Two records at the same offset compare equal, so one is dropped even if its tag, length, or checksum differs.

**Risk:** the parsed table count no longer matches the file, dependency resolution becomes nondeterministic, and deliberately aliased or malformed entries are hidden instead of validated.

**Fix:** preserve all records in a list sorted by `(offset, originalIndex)` and separately validate duplicate tags, identical ranges, overlaps, and aliases according to an explicit policy.

**Priority: P1 directory integrity.**

### 25. Table overlap, duplicate tags, and directory/header consistency are not validated

The parser ignores `searchRange`, `entrySelector`, and `rangeShift`, accepts duplicate tags, and does not reject table ranges overlapping the directory or each other. `AddTable` later overwrites duplicate tags.

**Fix:** validate the offset-table invariants, tag uniqueness, four-byte alignment where required, range ordering, and overlap policy before parsing any table payload.

**Priority: P1 structural validation.**

### 26. Checksum failures are diagnostics only

A table checksum mismatch only writes to `Debug`; release consumers receive a successfully parsed font with no warning or failure policy. The whole-font checksum adjustment is not validated during reading.

**Fix:** expose strict and permissive parsing modes. Strict mode should reject checksum mismatches; permissive mode should return structured diagnostics attached to the parsed font.

**Priority: P1 integrity semantics.**

### 27. Non-seekable streams are copied without a size limit and the temporary stream is not owned explicitly

`ParseFont(Stream)` copies the complete source into a `MemoryStream` with no maximum length. A hostile or endless stream can exhaust memory. The replacement stream is not disposed deterministically.

**Fix:** accept parser options with a maximum font size, copy incrementally with cancellation in an async overload, and dispose the owned temporary stream after parsing while preserving the caller stream ownership contract.

**Priority: P1 resource exhaustion.**

### 28. Parsing materializes every table before table-specific parsing

Each directory entry is copied into a separate `MemoryStream`, duplicating potentially most of the font in memory in addition to the original byte array or copied source stream.

**Fix:** use bounded slices over the original seekable stream, or copy only when required. Enforce per-table and total allocation budgets.

**Priority: P1 memory amplification.**

### 29. Static `RawReader` and `RawWriter` instances are shared without an explicit thread-safety contract

All font parsing and writing uses shared mutable serializer objects. Their delegate registries and configuration originate outside this package and are not demonstrated to be immutable or concurrency-safe.

**Fix:** make the serializer configuration immutable and document thread safety, or create per-operation reader/writer configurations.

**Priority: P1 concurrency safety.**

### 30. Composite glyph indices are stored as signed `short`

`GlyphCompound.GlyfComponent.GlyphIndex` is a `short` and is read/written as `Int16`, but the glyph index field is unsigned. Fonts with glyph IDs above 32767 become negative.

**Fix:** use `ushort` or a validated `int` throughout and reject component indices outside `maxp.numGlyphs`.

**Priority: P1 glyph correctness.**

### 31. Composite glyph references are not validated for cycles or excessive expansion

The parser limits the number of direct components to 1000, but does not establish a maximum recursive depth, expanded point count, or cycle detection policy when compound glyphs reference other compound glyphs.

**Risk:** cyclic or exponentially expanding component graphs can cause recursion failures, CPU exhaustion, or very large allocations during glyph resolution/rendering.

**Fix:** resolve through a guarded context containing the active glyph stack, maximum depth, maximum expanded components/points, and a deterministic cycle error.

**Priority: P1 hostile-font complexity.**

### 32. Composite glyph length narrows to `short`

`GlyphCompound.Length` accumulates into `int` and returns `(short)size`. Oversized instruction/component data wraps to a negative or smaller length, corrupting `glyf` layout and regenerated `loca` offsets.

**Fix:** keep all table and glyph lengths as checked `int`/`uint`; validate format maxima before serialization and remove narrowing casts from public/internal length contracts.

**Priority: P1 serialization integrity.**

### 33. `loca` offsets are not validated after reading

The table accepts decreasing offsets, negative values, offsets beyond `glyf`, and a final offset inconsistent with the glyph table. Its indexer then returns negative sizes directly.

**Fix:** after loading `loca`, require exactly `numGlyphs + 1` entries, non-decreasing offsets, valid alignment for the selected format, and a final offset within the associated `glyf` length.

**Priority: P1 cross-table invariant.**

### 34. `cmap` uses signed counts and unchecked offsets

`numberSubtables` is read as `Int16` and subtable offsets as signed `Int32`. Negative counts or offsets and out-of-range offset differences are allowed to reach array allocation and `Slice`.

**Fix:** parse unsigned fields, cap subtable count, validate each offset against the cmap table bounds, and calculate lengths using checked arithmetic before creating a slice.

**Priority: P1 untrusted-input parsing.**

### 35. Malformed cmap subtables are silently discarded

`CmapTable.ReadData` catches a broad family of exceptions and only writes to `Debug`. A font can therefore load successfully with all useful mappings removed, and callers cannot distinguish unsupported formats from corruption.

**Fix:** return structured diagnostics and define strict/permissive behavior. Never hide programming exceptions; catch only parser-domain failures with the subtable byte range and format context.

**Priority: P1 observable failure semantics.**

### 36. Mutable arrays expose internal cmap and compound-glyph state

`CmapTable.CMaps` returns its internal array directly, and `GlyphCompound.Instructions` exposes the backing byte array. Callers can mutate parsed state without updating lengths, ordering, checksums, or related tables.

**Fix:** expose immutable/read-only collections and defensive copies, or provide validated mutation APIs that invalidate dependent caches and offsets.

**Priority: P1 state integrity.**

## Medium-priority findings

### 37. Zero-table fonts break derived header properties

`SearchRange` and `EntrySelector` call `BitOperations.Log2((uint)TablesCount)`. A newly constructed font with no tables has no explicit serialization contract and can produce nonsensical values.

**Fix:** reject serialization without required tables, or define zero-table values explicitly before invoking `Log2`.

**Priority: P2 API predictability.**

### 38. Table type discovery depends on unrestricted assembly reflection and unique attributes

The static constructor scans every subclass and calls `Dictionary.Add`. A duplicate table attribute anywhere in the assembly causes type initialization failure for the entire package.

**Fix:** use an explicit registry or source-generated registration, detect duplicates with a precise diagnostic, and validate constructibility at build/test time.

**Priority: P2 startup robustness.**

### 39. Package-wide preview language/features are enabled without a demonstrated need

The project targets `net8.0` but enables preview features and `LangVersion=Latest`, making reproducibility dependent on the installed SDK and broadening consumer compatibility risk.

**Fix:** pin the language version and disable preview features unless a documented public API requires them.

**Priority: P2 packaging stability.**

## Required regression tests

- Read short `loca` values `0x7FFF`, `0x8000`, and `0xFFFF`; verify unsigned byte offsets.
- Reject odd, decreasing, negative, overflowing, and out-of-`glyf` loca offsets; automatically select long format when required.
- Fuzz directory counts, offsets, lengths, duplicate tags, duplicate offsets, overlaps, and arithmetic overflow.
- Verify strict/permissive checksum behavior and structured diagnostics.
- Parse a bounded non-seekable stream and reject input above the configured total size.
- Measure peak allocations to ensure tables are not duplicated unnecessarily.
- Parse and write compound glyph IDs above 32767.
- Reject cyclic and excessively deep compound-glyph graphs.
- Reject wrapped glyph lengths and excessive instruction blocks.
- Fuzz cmap counts/offsets and verify malformed subtables are observable rather than silently lost.
- Prove returned cmap/instruction collections cannot mutate internal state.
- Serialize an empty/incomplete font and assert the chosen explicit contract.

## Recommended order

| Priority | Action |
|---|---|
| P0 | Correct unsigned short `loca` handling and validate all SFNT table ranges |
| P1 | Enforce directory, loca/glyf, cmap, and compound-glyph cross-table invariants |
| P1 | Add parser allocation/depth limits and structured strict/permissive diagnostics |
| P1 | Make parsed collections immutable and clarify serializer thread safety |
| P2 | Stabilize registry initialization and package compiler settings |

## Deployment warning

Until these findings are addressed, do not parse untrusted fonts in-process without an external file-size limit and execution isolation. Avoid writing fonts that use short `loca` when any glyph boundary is odd or exceeds the representable range, and do not rely on checksum validation or cmap completeness as evidence that a parsed font is intact.

## Resolution status (items 21-39) -- addressed 2026-08-04

All 19 findings below were addressed on branch `claude/fonts-todo-pass2-p21-39`. The deployment
warning above no longer applies when `TrueTypeFontParsingOptions` limits are configured
appropriately for the trust level of the input; see `README.md` and
`docs/releasing/MigrationTo2.0.md#omy-utils-fonts-2` for usage and the full list of 2.0 API breaks.

New shared infrastructure (`Utils.Fonts/TTF/Parsing/`): `TrueTypeFontParsingOptions`,
`TrueTypeFontWritingOptions`, `FontValidationMode`, `FontDiagnostic(Code/Severity)`,
`FontParseException`, `FontParsingContext` (internal), `TableDirectoryEntry` (internal),
`TableChecksum` (internal, read-only checksum computation), `CompositeGlyphResolutionContext`
(internal).

### 21. Short-format `loca` entries parsed as signed values -- **Fixed**
- Resolution: `LocaTable.ReadData` reads `UInt16` and widens before doubling; `0x8000..0xFFFF` now produce `65536..131070`, never negative.
- Files: `TTF/Tables/LocaTable.cs`.
- Tests: `LocaTableTests.ShortFormat_BoundaryValues_WidenToUnsignedByteOffsets` (0x0000/0x7FFF/0x8000/0xFFFF).
- API breaks: none (internal `int[]` representation unchanged; public `(offset,size)` indexer unchanged).

### 22. Short-format `loca` serialization silently truncates -- **Fixed**
- Resolution: new `LocaTable.PrepareForSerialization()` recomputes offsets from actual glyph lengths and automatically selects short vs. long format (even offsets, `offset/2 <= ushort.MaxValue`), updating `HeadTable.IndexToLocFormat`. Called once, up front, by `TrueTypeFont.WriteFont`/`PrepareForSerialization` instead of as a side effect of reading `Length`.
- Files: `TTF/Tables/LocaTable.cs`, `TTF/TrueTypeFont.cs`.
- Tests: `LocaTableTests.PrepareForSerialization_AllOffsetsEvenAndSmall_SelectsShortFormat`, plus the pre-existing short/long round-trip tests (still passing, now via the explicit prepare phase).
- API breaks: `LocaTable.Length`/`WriteData` no longer implicitly refresh offsets from `glyf` as a read side effect (internal behavior change; no public signature change).

### 23. SFNT directory signed/unbounded fields -- **Fixed**
- Resolution: `numTables`/table `checksum`/`offset`/`length` read as `UInt16`/`UInt32`; `directoryLength = checked(12L + numTables*16L)` validated against the font length before any directory entry is read; every entry's `end = checked(offset + length)` validated against the font length and `MaximumTableBytes` before any seek/slice/allocation.
- Files: `TTF/TrueTypeFont.cs` (`ParseFont(Reader,...)`, `ValidateDirectory`), `TTF/Parsing/TableDirectoryEntry.cs`.
- Tests: `TrueTypeFontDirectoryTests` (`NumTables_HighBit_*`, `TruncatedDirectory_*`, `OffsetWithHighBit_*`, `OffsetPlusLength_OverflowsUInt32_*`, `MaximumTables_*`, `MaximumTableBytes_*`, `MaximumFontBytes_*`).
- API breaks: `TrueTypeFont.TablesCount`/`SearchRange`/`EntrySelector`/`RangeShift` are `ushort` (were `short`); new `TrueTypeFontParsingOptions`-taking `ParseFont` overloads.

### 24. Duplicate directory offsets silently discarded (`SortedSet`) -- **Fixed**
- Resolution: replaced `SortedSet<TableDeclaration>` (compared by `Offset` alone) with a `List<TableDirectoryEntry>` preserving every record, sorted by `(Offset, OriginalIndex)` only for overlap detection; duplicate tags, exact aliases, and overlaps are each detected and policy-driven (strict rejects, permissive diagnoses and keeps a defined subset).
- Files: `TTF/TrueTypeFont.cs` (`ValidateDirectory`, `DetectOverlaps`), `TTF/Parsing/TableDirectoryEntry.cs`.
- Tests: `DuplicateTag_IsRejectedInStrictMode`, `DuplicateTag_KeepsFirstEntryInPermissiveMode`, `ExactAlias_IsRejectedInStrictMode_AndDiagnosedInPermissive`, `PartialOverlap_IsRejectedInStrictMode_AndDiagnosedInPermissive`.
- API breaks: `TrueTypeFont.TableDeclaration` (public nested class) removed; not referenced elsewhere in the codebase.

### 25. Table overlap / duplicate tags / directory consistency unvalidated -- **Fixed**
- Resolution: `ValidateDerivedOffsetTableFields` checks `searchRange`/`entrySelector`/`rangeShift` against the values implied by `numTables` (policy-dependent); tables overlapping the directory region are rejected/diagnosed; 4-byte misalignment is a permissive-mode warning.
- Files: `TTF/TrueTypeFont.cs`.
- Tests: `TableOverlappingDirectory_*`, `DerivedOffsetTableFields_Mismatch_IsRejectedInStrictMode`.
- API breaks: none beyond those already listed under item 23.

### 26. Checksum failures are diagnostics only -- **Fixed**
- Resolution: table and whole-font checksums use the new read-only `TableChecksum.ComputeTableChecksum` (never mutates the source stream, unlike the previous `ReaderWriter`-based zeroing of `head.checksumAdjustment`); mismatches are policy-dependent (`FontDiagnosticCode.TableChecksumMismatch`/`FontChecksumMismatch`) via `FontParsingContext`. Fonts with no `head` table skip the whole-font check (no checksumAdjustment slot to satisfy the identity).
- Files: `TTF/Parsing/TableChecksum.cs`, `TTF/TrueTypeFont.cs` (`ParseDirectories`, `VerifyFontChecksum`, `UpdateChecksumAdj`, `WriteFont`).
- Tests: `TableChecksumMismatch_IsRejectedInStrictMode_AndDiagnosedInPermissive`, `WholeFontChecksum_ValidForATrulyWrittenFont`, `WholeFontChecksum_Invalid_IsRejectedInStrictMode_ButPerTableChecksumsStillPass`.
- API breaks: none beyond the new options/diagnostics types.

### 27. Non-seekable streams copied without a size limit -- **Fixed**
- Resolution: `CopyToBoundedSeekableStream`/`...Async` copy in 80 KiB blocks, rejecting the input as soon as `MaximumFontBytes` would be exceeded rather than after buffering it in full; the owned temporary buffer is always disposed; `LeaveOpen` governs only the caller-supplied stream.
- Files: `TTF/TrueTypeFont.cs`.
- Tests: `MaximumFontBytes_Exceeded_NonSeekableStream_IsRejectedDuringCopy`, `NonSeekableStream_WithinLimit_ParsesSuccessfully`, `MaximumFontBytes_ExactAndExceeded_ByteArray`.
- API breaks: new `ParseFontAsync` overload; `ParseFont(Stream, options)` behavior change (previously unbounded).

### 28. Tables materialized before table-specific parsing -- **Fixed**
- Resolution: `ParseDirectories` reads each table via `data.Slice(entry.Offset, entry.Length)` -- a bounded, independent `PartialStream` view over the original source stream -- instead of `data.ReadBytes(...)` into a fresh `MemoryStream` per table. Checksums are computed by seeking directly in the source stream (`TableChecksum`), not from a duplicated buffer.
- Files: `TTF/TrueTypeFont.cs`.
- Tests: covered indirectly by every parsing test (no table is readable at all without a correct bounded slice); no dedicated allocation/byte-count benchmark was added, per guidance against fragile exact-allocation assertions in ordinary unit tests.
- Remaining limitation: each table still materializes its *own* parsed representation (e.g. `GlyphSimple`'s point arrays) -- that is expected and unrelated to this item, which was specifically about avoiding a redundant raw-byte copy per table before parsing even begins.

### 29. Shared `RawReader`/`RawWriter` without a documented thread-safety contract -- **Fixed (documented)**
- Resolution: `TrueTypeFont.rawReader`/`rawWriter` are configuration-only (immutable delegate lists built once); every parse/write constructs its own `Reader`/`Writer` with independent position-stack state. `PartialStream` (the bounded-slice primitive introduced for item 28) is already thread-safe -- it serializes all operations on a given underlying stream through a shared `SemaphoreSlim` (see `Utils.IO/IO/PartialStream.cs`, exercised by `PartialStreamConcurrencyTests`).
- Files: `TTF/TrueTypeFont.cs` (doc comment on the `TablesType` field).
- Tests: no new Utils.Fonts-level concurrent-parsing stress test was added in this pass; the underlying `PartialStream` concurrency contract is already covered by `UtilsTest/Streams/PartialStreamConcurrencyTests.cs`.
- Remaining limitation: a dedicated "parse N fonts concurrently on N threads" Utils.Fonts test (spec section 27) is a reasonable follow-up not included here.

### 30. Composite glyph indices stored as signed `short` -- **Fixed**
- Resolution: `GlyfComponent.GlyphIndex` is `ushort`, read/written as `UInt16`; `GlyphCompound.getGlyphIndex` renamed to `GetGlyphIndex` (PascalCase) returning `ushort`; components are validated against `maxp.NumGlyphs` via `FontParsingContext` when a parsing context is active.
- Files: `TTF/Tables/Glyf/GlyphCompound.cs`, `TTF/Tables/GlyfTable.cs` (`NumGlyphs`, `TryGetGlyph`).
- Tests: `GlyphCompoundTests.GetGlyphIndex_AboveShortMaxValue_ReturnsUnsignedValue`.
- Remaining limitation: no dedicated end-to-end (full `TrueTypeFont.ParseFont`) strict-vs-permissive test for an out-of-range component reference was added; the validation code path (`GlyphCompound.ValidateComponentReferences`) is exercised implicitly (it is a no-op without a parsing context, which every direct-construction test in `GlyphCompoundTests` relies on) but not asserted against directly.
- API breaks: see item 23 summary in `AcceptedApiBreaks.md#omy-utils-fonts`.

### 31. Composite glyph cycles/unbounded expansion unvalidated -- **Fixed**
- Resolution: `CompositeGlyphResolutionContext` (active-glyph stack, depth, expanded component/point counters) is threaded through `GlyphBase.ResolveContours`/`GlyphCompound.ResolveContours`, shared across the whole expansion of a top-level glyph (not reset per recursive call), and cached after first resolution (`GlyphCompound.Contours` no longer re-walks/re-validates on every access). Cycle/depth/budget violations always throw (`FontParsingContext.Reject`), in both validation modes.
- Files: `TTF/Tables/Glyf/GlyphBase.cs`, `TTF/Tables/Glyf/GlyphCompound.cs`, `TTF/Parsing/CompositeGlyphResolutionContext.cs`.
- Tests: `DirectSelfReference_ThrowsOnContoursResolution`, `IndirectCycle_ThrowsOnContoursResolution`, `ExcessivelyDeepChain_ThrowsMaximumCompositeDepthExceeded`.
- Remaining limitation: `MaximumExpandedComponents`/`MaximumExpandedPoints` are implemented and enforced by the same code path exercised by the depth test, but have no dedicated test (constructing a synthetic font that legitimately reaches the default 100,000-component/2,000,000-point budgets is impractical for a fast unit test).

### 32. Composite glyph length narrows to `short` -- **Fixed**
- Resolution: `GlyphBase.Length`/`GlyphSimple.Length`/`GlyphCompound.Length` return `int`; all narrowing `(short)` casts removed; accumulation uses `checked` arithmetic in `LocaTable.PrepareForSerialization`.
- Files: `TTF/Tables/Glyf/GlyphBase.cs`, `TTF/Tables/Glyf/GlyphSimple.cs`, `TTF/Tables/Glyf/GlyphCompound.cs`.
- Tests: existing round-trip tests continue to pass under the new `int` return type; no dedicated ">32767-byte glyph" test was added (would require an impractically large synthetic glyph for a fast unit test).
- API breaks: see `AcceptedApiBreaks.md#omy-utils-fonts`.

### 33. `loca` offsets unvalidated after reading -- **Fixed**
- Resolution: `LocaTable.ReadData` requires exactly `GlyphCount + 1` entries (implicit in the fixed-size `ReadArray` call) and non-decreasing offsets (always fatal, both modes); `GlyfTable.ReadData` re-validates `offset + size <= glyf length` defensively, as a local invariant independent of `loca` having been constructed through the normal pipeline.
- Files: `TTF/Tables/LocaTable.cs`, `TTF/Tables/GlyfTable.cs`.
- Tests: `LocaTableTests.ReadData_DecreasingOffsets_Throws`, `ReadData_LongFormat_OffsetAboveIntMaxValue_Throws`.

### 34. `cmap` signed counts / unchecked offsets -- **Fixed**
- Resolution: `numberSubtables`/platform/encoding IDs read as `UInt16`, offsets as `UInt32`; `numberSubtables` bounded by `MaximumCmapSubtables` (always fatal) before any allocation; `directoryEnd = checked(4L + numberSubtables*8L)` validated against the table length; each record's offset validated against `[directoryEnd, cmapLength)` before any slice.
- Files: `TTF/Tables/CmapTable.cs`, `TTF/Tables/Cmap/CMapFormatBase.cs` (subtable-declared length also checked against its slice).
- Tests: `CmapTableTests.NumberSubtables_ExceedingLimit_Throws`, `TruncatedSubtableDirectory_Throws`, `SubtableOffset_OutsideCmapTable_Throws`, `SubtableOffset_InsideDirectory_Throws`.
- API breaks: `CmapTable.Version`/`NumberSubtables` are `ushort`; `AddCMap`/`RemoveCMap`/`GetCMap` take `ushort` IDs.

### 35. Malformed `cmap` subtables silently discarded -- **Fixed**
- Resolution: removed the `Debug.WriteLine`-only catch; malformed subtables now go through `ReportOrReject` (policy-dependent when a `FontParsingContext` is active via the full `TrueTypeFont.ParseFont` pipeline; always throws `InvalidDataException` for a standalone `CmapTable.ReadData` call with no context). Only parser-domain exception types are caught (`InvalidDataException`, `FormatException`, `NotSupportedException`, `ArgumentException`, `OverflowException`, `IndexOutOfRangeException`); `OutOfMemoryException`, `StackOverflowException`, and `OperationCanceledException` are never caught.
- Files: `TTF/Tables/CmapTable.cs`.
- Tests: `CmapTableTests.MalformedSubtable_Throws`.
- Remaining limitation: a dedicated end-to-end (full `TrueTypeFont.ParseFont`, permissive mode) test showing a malformed `cmap` subtable diagnosed-and-skipped while the rest of the font loads was not added; `TrueTypeFontDirectoryTests` covers the equivalent strict/permissive contract at the SFNT-directory level, and `MalformedSubtable_Throws` covers the underlying `CmapTable`-level rejection logic directly.

### 36. Mutable arrays expose internal `cmap`/compound-glyph state -- **Fixed**
- Resolution: `CmapTable.CMaps` returns a cached `ReadOnlyCollection<T>` snapshot (invalidated on `AddCMap`/`RemoveCMap`, never mutable in place); `GlyphCompound.Instructions` is `ReadOnlyMemory<byte>`.
- Files: `TTF/Tables/CmapTable.cs`, `TTF/Tables/Glyf/GlyphCompound.cs`.
- Tests: `CmapTableTests.CMaps_SnapshotDoesNotReflectLaterMutation`, `GlyphCompoundTests.Instructions_IsReadOnlyMemory`.
- API breaks: see item 34/30 summaries.

### 37. Zero-table fonts break derived header properties -- **Fixed**
- Resolution: `TrueTypeFont.SearchRange`/`EntrySelector`/`RangeShift` explicitly return `0` when `TablesCount == 0`, instead of relying on `BitOperations.Log2(0)`'s implementation-defined-looking behavior.
- Files: `TTF/TrueTypeFont.cs`.
- Tests: `TrueTypeFontDirectoryTests.ZeroTableFont_HasExplicitZeroDerivedHeaderValues`.

### 38. Table registry depends on unrestricted reflection with late failure -- **Fixed**
- Resolution: registry construction factored into `TrueTypeFont.BuildTablesTypeRegistry()` (internal, unit-testable independent of the lazy static constructor), which explicitly rejects abstract declared types, types with no accessible parameterless constructor, duplicate tags (with both offending type names in the message), and dependency cycles in `TTFTableAttribute.DependsOn` -- each with a precise `InvalidOperationException`, rather than a duplicate-key `ArgumentException` surfacing only as an opaque `TypeInitializationException` on first use.
- Files: `TTF/TrueTypeFont.cs`. `Utils.Fonts.csproj` gained `InternalsVisibleTo` for `UtilsTest.Unit`/`UtilsTest.Functional` so this internal method (and `HeadTable.ChecksumAdjustmentOffset`) are directly testable.
- Tests: `TrueTypeFontDirectoryTests.TableRegistry_BuildsWithoutDuplicateTagsOrCycles`.
- Remaining limitation: the registry remains a runtime reflection scan over the assembly (not a source generator or a fully static/generated table); a source-generator-based registry was judged out of scope for this pass and would be a natural follow-up.

### 39. Preview language features enabled without demonstrated need -- **Fixed**
- Resolution: removed `EnablePreviewFeatures`, pinned `LangVersion` to `13.0`. A full solution build confirmed no source in the package actually required a preview-only feature.
- Files: `Utils.Fonts/Utils.Fonts.csproj`.
- Tests: build validation only (packaging change, no runtime behavior).
