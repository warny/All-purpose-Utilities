# Utils.NumberToString audit closures — 2026-10-08 (NTS-25B, NTS-25 closed)

NTS-25B closes NTS-25 (localized Conway names in derived scales; NTS-25A is in `DONE-2026-10-08(1).md`).
Indonesian, Malay, Swahili and Turkish now generate their Conway-Wechsler names from four tables adapted to
their own spelling, with the same mechanisms as their attested loans. Configuration only: no engine, public API
or XSD change (the NTS-25A comma marker lists are used as they are). Sources are in
`docs/NTS-08-linguistic-sources.md`, section "NTS-25B".

## Project rule

When a language has integrated the million/billion/trillion/quadrillion family under identifiable local forms,
the library permits a productive Conway-Wechsler extension using that language's spelling rules. Each name need
not be attested, but the prefixes are adapted with the same mechanisms as the loans the language already has.
Attested forms take priority over a proposed transformation.

## Final tables

Conway tables, units / tens / hundreds; `(start)` and `(end)` are the NTS-24 markers, `ks` the two-letter x-link.

## Turkish: attested morphemes preferred to the proposed ones

tr.wikipedia, *Büyük sayıların adları*, lists the Turkish series (corroborated for undesilyon, dodesilyon,
tredesilyon by two Turkish popular-science pages): undesilyon, **dodesilyon**, tredesilyon, **katordesilyon**,
kendesilyon, seksdesilyon, septendesilyon, oktodesilyon, novemdesilyon, vigintilyon, trigintilyon,
**katragintilyon**, **kenkagintilyon**, **sentilyon**. The proposed `duo`, `kattuor`, `kentua`, `kadraginta`,
`kentaginta` contradict them; the attested morphemes were kept: `do`, `kator`, `katragint`, `kenkagint`, and
`kenka` for the units quinqua (the morpheme of `kenkagintilyon`); `katringenti` and `kengenti` (not
`kadringenti`/`kentingenti`) follow `katri`/`katragint` and `kenti`/`kendesilyon`.

The series itself is the dictionary one (quindecillion, sexdecillion, novemdecillion); the strict Conway structure
adopted by NTS-24 for every language is kept, so n = 15, 16, 19 are `kenkadesilyon`, `sedesilyon`,
`novendesilyon`, not the attested `kendesilyon`, `seksdesilyon`, `novemdesilyon` (the same divergence as English
`quinquadecillion` against `quindecillion`). Every other attested form of the list is produced.

## Swahili: Wiktionary preferred to a library

Wiktionary has Swahili entries `kwadrilioni`, `kwintilioni`, `sekstilioni`, `desilioni` (borrowed from English),
which the tables follow. The `tarakimu` Python library spells `kuadrilioni`, `kuintilioni`, `seksitilioni`; it is
not used.

## Turkish n = 1000: `milnilyon` kept (`VoidGroup="ini"` not adopted)

`ini` would give `milinilyon` for n = 1000 but changes only the zero group: n = 1001 stays `milmilyon`, n = 1010
`mildesilyon`, n = 1 000 003 becomes `miliniltrilyon`. The pattern would then differ between a zero group and any
other group, which is less consistent than one junction everywhere. Turkish phonotactics accept `ln` and `lm`
inside a word (`yalnız`, `almak`), so `milnilyon` is not ill-formed. The faithful fix, a junction `li` between
groups and `l` before `yon`, needs a separate inter-group separator: an engine primitive, which the owner declined
in NTS-25A. The limitation stays documented for TR and UK.

## Forms changed from NTS-25A

| Culture | Examples (before → after) |
|---|---|
| ID, ID-ID | `deciliun` → `desiliun`, `quattuordeciliun` → `kuatuordesiliun`, `centiliun` → `sentiliun`; n = 1000 `miniliun` → `miliniliun` |
| MS, MS-MY | `decilion` → `desilion`, `quattuordecilion` → `kuatuordesilion`, `centilion` → `sentilion`; n = 1000 `minilion` → `milinilion` |
| SW, SW-KE, SW-TZ | `quadrilioni` → `kwadrilioni`, `quintilioni` → `kwintilioni`, `sextilioni` → `sekstilioni`, `octilioni` → `oktilioni`, `decilioni` → `desilioni`, `centilioni` → `sentilioni` |
| TR, TR-TR | `seksilyon` → `sekstilyon`, `decilyon` → `desilyon`, `duodecilyon` → `dodesilyon`, `quattuordecilyon` → `katordesilyon`, `centilyon` → `sentilyon` |

Unchanged: ID `triliun` … `noniliun`, MS `trilion` … `nonilion`, SW `milioni` … `trilioni`, `septilioni`,
`nonilioni`, TR `trilyon`, `katrilyon`, `kentilyon`, `septilyon`, `oktilyon`, `nonilyon`; TR n = 1000 `milnilyon`.

## Verification

- 73-culture dump against the NTS-25A head (per-culture random seed, every key matched): only ID, ID-ID, MS,
  MS-MY, SW, SW-KE, SW-TZ, TR and TR-TR changed; RU, BG, UK and every other culture are identical.

  attested forms on their own, MS inheriting the ID tables, the `ks` link never degraded to x, k or s, alphabet
  purity (SW and TR without q, x, c; ID and MS without qu, x, c) over indices 2–2101 and large ones, TR case
  variants on `sekstilyon`, `desilyon`, `vigintilyon`, `milnilyon`, localized cardinals, `IsUnbounded` and
  `CanNameGroup(int.MaxValue)`. NTS-24 and NTS-25A tests stay green (two NTS-25A expectations updated to the
  localized SW/TR names).
- ApiCompat strict against `master`: no breaking change.
