# Utils.NumberToString audit closures — 2026-10-08

NTS-24 (Conway-Wechsler scale names) is closed. The dynamic `NumberScale` generator and the shared
`SCALE-SHORT`/`SCALE-LONG` prefix tables now implement the strict Conway-Guy-Wechsler construction, including
indices above the 999th -illion. This is a correction of the shared Conway implementation, not an Ewe change:
every language inheriting `SCALE-SHORT` or `SCALE-LONG` receives the corrected names. No public API, XSD schema
or culture-specific code was added; the prefix-entry grammar gained a bracketed ending
(`[default|-illi=>form]`), decided with the project owner. Sources are in
`docs/NTS-08-linguistic-sources.md`, section "NTS-24".

## Convention

Strict Conway-Guy-Wechsler (project decision). `quinquadecillion`, `sedecillion` and `novendecillion` are its
systematic forms and stay; the dictionary `quindecillion`, `sexdecillion`, `novemdecillion` are not adopted.

## Old algorithm

`GetScaleName` computed the prefix value (the Conway index n) and its suffix, then:

- n ≤ 9: `Scale0Prefixes[n]` + `groupSeparator` + suffix;
- n ≥ 10: every group of three digits, the first one included, was composed from `UnitsPrefixes`,
  `TensPrefixes` and `HundredsPrefixes`; `000` gave `voidGroup`; the groups were joined by `groupSeparator`.

Consequences: a `001` group above the first one read `UnitsPrefixes[1]` (`uni`), so n = 1000 was
`unillinillion`; the last component of a group kept its intrinsic vowel (`trigintallion`); every linking
consonant shared by two components was inserted (`sesxoctogintacentillion`); `FirstLetterUppercase`
capitalized every group.

## New algorithm

```
GetScaleName(scale)
  static name?                        → StaticValues[scale]
  dynamicScale = scale - StaticValues.Count + StartIndex
  (quotient, remainder) = DivRem(dynamicScale, ScaleSuffixes.Count)
  BuildDynamicName(prefix = quotient + 1, suffix = ScaleSuffixes[remainder])
    split prefix into base-1000 groups (long division, at most 7 groups, no string parsing)
    for each group, most significant first:
      0        → voidGroup
      1..9     → Scale0Prefixes[group]      (empty entry → InvalidOperationException)
      10..999  → units + tens + hundreds, pre-parsed components:
                 each non-last component: its default text + the first of its (end) consonants
                 accepted by the next component's (start) markers
                 last component: its -illi- text
      append groupSeparator
    append suffix, capitalize once when FirstLetterUppercase
```

There is one group builder: the first group and every following one use the same rule, so they cannot
diverge again. The three composition tables are parsed once in the constructor (the regex no longer runs per
conversion); generation is O(number of groups).

### Why a `001` group uses `Scale0Prefixes`

Conway-Wechsler names an index above 999 as `XilliYilliZillion`, the (10^6 X + 10^3 Y + Z)-th -illion: each
group is itself a small Conway index, named exactly like a first-group index. A lone `1` is therefore `mi`
(as in million), not the compound units prefix `un` (as in undecillion): n = 1000 is `mi` + `lli` + `ni` +
`lli` + `on` = `millinillion`, n = 1001 is `millimillion`.

### Terminal-vowel rule

Conway replaces the final vowel of a group's prefix by `i` before `-illi-`/`-illion`. Only the round tens
ending in `a` are affected (`deci`, `viginti` and every hundreds root already end in `i`), and only when they
end their group: 30 `trigintillion`, but 130 `trigintacentillion`. Editing the table (`triginti`) would
break 130, and a hard-coded "last vowel → i" would impose a Latin rule on the generic public `NumberScale`,
so the rule is data: a units/tens/hundreds entry may end with `[default|-illi=>form]`, `form` being used when
the component is the last of its group (right before the `-illi-` junction, whatever `groupSeparator`
spells it: `lli`, `li`, `л`, `""`). The shared tens read `(ns)trigint[a|-illi=>i]` … `nonagint[a|-illi=>i]`.
Only the `-illi` context exists; another context, a second `-illi` or an alternative without `=>` is
rejected with `ArgumentException` when the scale is built. A non-empty entry must match the grammar completely
(anchored pattern): leading or trailing text (`trigint[a|-illi=>i]garbage`, `-trigint`) is rejected too.

### Linking consonants

Conway inserts at most one linking consonant. The generator now inserts the first of the component's
`(end)` letters accepted by the next component's `(start)` markers. `tre` takes an `s` before an s- or
x-marked component; the grammar has no "x gives s" form, so the x-marked components also carry `s`, as
`octoginta`/`octingenti` already did: `(nxs)centi`, `(mxs)octoginta`, `(mxs)octingenti`. `se(xs)` lists `x`
first, so `se` + `centi` stays `sexcenti`.

### VoidGroup

Unchanged: `voidGroup` (default `ni`, an explicit value is kept) names every zero group, never removed:
n = 1 000 003 is `mi|ni|tri` = `millinillitrillion`.

## SCALE-SHORT and SCALE-LONG

Both cultures carried the same erroneous tables and both are corrected identically. The index mapping was
audited separately:

- SCALE-SHORT (two static names, one suffix `on`): scale index = Conway n + 1 (index 2 = million, n = 1).
- SCALE-LONG (two static names, suffixes `on`, `ard`): scale index 2n is `…on`, 2n + 1 is `…ard`
  (index 2 = million, 3 = milliard, 2000 = millinillion, 2001 = millinilliard).
- Offsets (`startIndex` of HU/ID/TR, static millions) only change which index reaches the generator, not the
  Conway index it receives.

`NumberScaleContractTests` checks both against the same literal reference table (n = 1–20, 21–99 linking
cases, round tens, 100–999 triplet boundaries, 1000, 1001, 1009, 1010, 1030, 1100, 1999, 2000, 6560, 30000,
1 000 003), plus the published 10^33,002,010,111 example through the internal builder (n exceeds `int`).

## Blast radius (73-culture dump)

The 73 configured cultures were dumped before and after (scale names 0–419, 990–1014, 1990–2014,
3000–3009, 10^6–10^6+9, 2·10^6–2·10^6+9 with `CanNameGroup`; 10^0–10^399 by thousands; 60 random cardinals
up to 119 digits; ordinals 0–1100). 16 734 lines differ, all in the inheritors of `SCALE-SHORT` or
`SCALE-LONG`, and all are expected Conway corrections; no ordinal, `IsUnbounded` or nameability changed:

- SCALE-SHORT family: SCALE-SHORT, EN, EN-GB, EN-uk, EN-us, EE, ID, ID-ID, MS, MS-MY (through ID), SW, SW-KE,
  SW-TZ, TR, TR-TR.
- SCALE-LONG family: SCALE-LONG, BG, BG-BG, CS, CS-CZ, DA, DA-DK, DE, de-CH, de-LI, FR, FR-be, FR-ca, FR-ch,
  FR-fr, HR, HR-HR, HU, HU-HU, IT, NB, NB-NO, NO, RU, SK, SK-SK, SV, SV-SE, UK, UK-UA.
- Every changed cardinal is explained by the changed scale names. Two secondary effects, both corrections:
  German `eins Trigintallion` → `eine Trigintillion` (the feminine-article rule matches `-illion` and no
  longer misses the old misspelled name); in ID, MS, SW and TR (`groupSeparator=""`) the old n = 12 and
  n = 2010 were both `duodec…`, now `duodec…` and `bidec…`.
- Unchanged (28 cultures): AR, CA, ca-ES, ca-ES-valencia, EL, ES, EU, eu-ES, FA, FA-IR, FI, GL, gl-ES, HE, HI,
  JA, KO, NL, PL, PT, RO, RO-RO, VI, VI-VN, VN, WO, ZH, ZU.

### EE (inherited effect)

No Ewe configuration change: `unideciliɔn` → `undeciliɔn`, `vingtiliɔn` → `vigintiliɔn`, `trigintaliɔn`
→ `trigintiliɔn`, `uniliniliɔn` → `miliniliɔn` (10^3003), with exactly the English roots.

### ID

`ID` declared `Scale0Prefixes` 1 and 2 as empty placeholders (juta and miliar are static names). Every 1..9
entry is now reachable from a higher group, so they are set to `mi` and `bi` (project decision); without
them n = 1000 would have been `niliun`. Empty `Scale0Prefixes[1..9]` entries now make `IsUnbounded` false and
the affected groups unnameable instead of producing a degenerate name. The same holds for entries 1–9 of
`UnitsPrefixes`, `TensPrefixes` and `HundredsPrefixes`: an empty one is never silently dropped; it makes
`IsUnbounded` false and the 10..999 groups that need it (e.g. 011 for an empty units entry 1) unnameable
(review of PR #626). No built-in configuration is affected (identical dump). No "start per group" setting is
needed: `startIndex` already positions the first group, and Conway restarts every following group at the
same tables.

## Tests

- `NumberScaleContractTests`: SCALE-SHORT and SCALE-LONG reference tables, the published multi-group example,
  large nameable indices, synthetic tables (`001` in a higher group uses `Scale0Prefixes`, `-illi` endings,
  rejected endings, single linking consonant, empty `Scale0Prefixes` entry, empty units/tens/hundreds entry,
  entries with leading or trailing text), DE capitalization once per name. `ShortScale_ConwayWechsler_KnownTableErrors`, which pinned the bugs, is removed.
- `NumberToStringNts23Tests`: Ewe strict names, including `trigintiliɔn` and grouped indices.
- Features: English (outline rows 10^36, 10^63, 10^75, 10^93 and the long cardinal), French, French regional,
  German long cardinals.

## Limitations recorded (NTS-25), pre-existing and out of scope

- With `groupSeparator=""` (ID, MS, SW, TR) the suffix carries the `-li-` sound, so groups above the first one
  are joined without any junction (ID n = 1000 `miniliun`, SW `minilioni`, TR `minilyon`).
- BG, RU and UK override `Scale0Prefixes` in Cyrillic but inherit the Latin units/tens/hundreds tables and the
  Latin `voidGroup`, so names from the 10th -illion mix scripts (RU n = 1000 `миллиniллион`, as before the fix
  `uniллиniллион`).
