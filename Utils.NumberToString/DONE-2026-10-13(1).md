# Utils.NumberToString audit closure — 2026-10-13 (NTS-30A: decimal reading modes)

## NTS-30A — decimal reading modes, decimal zeros, fallback limit, mathematical fractions

NTS-30 recorded (found by NTS-27): "All languages: zero digits after the decimal separator are dropped". The pass
split that item out as NTS-30A and widened it: the decimal path conflated named mathematical fractions,
digit-by-digit reading and the language's choice between them. The other NTS-30 items stay open in `TODO.md`.

### 1. Original defect

`Convert(decimal, …)` read the decimal part either as a numerator over a configured `<Fraction>`
(`21.05` → `twenty-one point five hundredths`) or, without one, digit by digit, where every 0 vanished and left a
double space:

| Converter | Call | Before |
|---|---|---|
| NL | `21.05m` | `eenentwintig komma  vijf` |
| JA | `21.05m` | `二十一点五` |
| ZH | `21.05m` | `二十一点五` |
| NL | `Convert(21m, 2)` | `eenentwintig komma` |
| FR | `0.0001m` | `zéro virgule    et un` (no fraction beyond three digits; `et un` for 1) |

### 2. Zero-digit root cause

```csharp
foreach (char c in digits)
{
    int d = c - '0';
    result.Append(_defaultGroupTable.Digits[1][d].StringValue).Append(Separator);
}
```

The level-1 table is a composition table: `<Digit digit="0" string="" />` is an empty position (`105` is not
*one hundred zero five*), and in three languages a non-zero digit is a composition form too: FR `et un`
(*vingt et un*), DE `ein` (*einundzwanzig*; the standalone *eins* only appeared at the end of a phrase through the
German finalization), HU `két` (attributive). A pronounced decimal digit is a standalone numeral.

New logic (`BuildDecimalDigits`, `DecimalDigitTexts`, computed once per converter):

```csharp
_decimalDigitTexts ??= [.. Enumerable.Range(0, 10)
    .Select(d => DecimalDigitForms.TryGetValue(d, out var form)
        ? form
        : d == 0 ? Zero : BuildCardinalFragment(d, BuildVariantQuery([])))];
```

A 0 is `Zero`; 1–9 are their standalone cardinal fragments, which already apply `<Exceptions>` (FR `1 → un`,
HU `2 → kettő`); a language whose standalone form is not a fragment declares it in the new `<DecimalDigits>`
section (DE `<DecimalDigit digit="1" string="eins" />`: its fragment is the composition form `ein`, and `eins` was
only produced by the German finalizer). Over all 74 keys the pronounced 1–9 differ from the level-1 text in FR, DE
and HU only. These are fragments: the language finalizer runs exactly once, on the complete phrase.

Review round (PR #636, commit 452b3fed): the first version built the digit forms with
`LanguageSpecifics.FinalizeWriting(…, BuildCardinalFragment(d))`, i.e. up to nine finalizations of internal
fragments before the phrase's own, against the single-finalization contract of `INumberToStringLanguageSpecifics`
and `FinalizePhrase` (a non-idempotent finalizer would also have left finalized fragments inside the phrase). The
existing `Convert_CardinalAndDecimals_FinalizeCompletePhraseOnce` missed it because `2.25` in EN takes a
`<Fraction>`. Written first: `Convert_DigitByDigitDecimal_FinalizesCompletePhraseOnce` and
`Convert_MathematicalFractionDecimal_FinalizesCompletePhraseOnce` (`RecordingFinalizer`, a real pass through
`BuildDecimalDigits` with zeros and several digits, first call included) — the digit-by-digit one failed. Fixed by
the lexical `<DecimalDigits>` section above (XSD: digit 0–9, non-empty string; loader: no duplicate; `baseOn`:
inherited or replaced as a whole; options `DecimalDigitForms` validated and cloned). All 74 dumps, new modes
included, are byte-identical to the first version.

### 3. Reading strategy API

`DecimalFormatOptions.ReadingMode` (`DecimalReadingMode`, default `LanguageDefault`):

| Mode | Reads | `NotSupportedException` when |
|---|---|---|
| `LanguageDefault` | the configured `<Fraction>`; otherwise the digits, within `decimalDigitByDigitMaxDigits` | no fraction and more digits than the limit |
| `DigitByDigit` | every digit after the decimal separator word | never |
| `MathematicalFraction` | numerator over the named 10^n, without the separator word: alone for a zero integer part, after `integer + mixedFractionSeparator` otherwise; a zero decimal part is not read | no fraction for the digit count; non-zero integer part without `mixedFractionSeparator` |

Precedence: caller `DecimalSuffix` (unchanged contract: "always converted as a whole number regardless of …",
now also regardless of the mode) → `ReadingMode` → configured fraction → language fallback. `OmitZeroDecimals`
suppresses a zero decimal part in every mode. `mandatoryDecimalDigits` pads before the strategy, so
`Convert(21.5m, 3, MathematicalFraction)` keeps the precision: *vingt et un et cinq cents millièmes* (500/1000, not
reduced, as the existing named branch already did). A zero decimal part in `MathematicalFraction` gives the integer
alone (*deux*, not *deux et zéro dix-millième*). Negative values take the `minus` template around the whole phrase
(*moins un dix-millième*).

Implementation: `Convert(decimal, int, DecimalFormatOptions?, string[])` selects the strategy; private helpers
`AppendDecimalSeparatorWord`, `BuildNamedDecimalFraction`, `BuildDecimalDigits`, `BuildLanguageDefaultDecimal`,
`BuildMixedDecimalFraction`.

### 4. Language configuration

- `decimalDigitByDigitMaxDigits` (`xs:nonNegativeInteger`): absent = unlimited (backward compatible), `0` = no
  automatic fallback, `N` = fallback up to N digits; ignored by `DigitByDigit` and by a caller `DecimalSuffix`.
  Kept as a raw string through the XML model and the `baseOn` merge, so an explicit `0` overrides a base value;
  validated at load (non-negative integer) and in the converter constructor (`ArgumentOutOfRangeException`).
- `mixedFractionSeparator`: the connector of a mixed number, distinct from `decimalSeparator`. Two languages justify
  it: FR `et` (Éduscol) and EN `and` (OpenStax). Absent: `MathematicalFraction` fails closed for a non-zero integer
  part.
- `<DecimalDigits>`: the forms of the pronounced decimal digits that differ from the default (section 2).
- All three on `LanguageXmlModel`, `LanguageType`, `NumberToStringConverterOptions` (copied by the cloning
  constructor) and `NumberToStringConverter`; documented in the XSD and the README.
- No shipped language declares a fallback limit: neither audited language justified one (French reading *2 virgule
  4* is current usage per Éduscol; English *point* reading is common).

### 5. French audit (sources: `docs/NTS-08-linguistic-sources.md`, section NTS-30A)

| Digits | Denominator | Source | Status |
|---|---|---|---|
| 1–3 | dixième, centième, millième | OQLF BDL "Écriture des fractions" | unchanged |
| 4 | dix-millième | OQLF BDL: *quatre-vingts dix-millièmes (80/10 000)* | attested |
| 5 | cent-millième | OQLF BDL: *cinq cent-millièmes (5/100 000)* | attested |
| 6 | millionième | Académie 9e éd.: *Un millionième ou 1/1 000 000*, *Trois millionièmes* | attested |
| 7, 8 | dix-millionième, cent-millionième | hyphenated compound denominator (OQLF BDL; Académie 2022 on *vingt cinq-millièmes*) on attested *millionième* | productive rule |
| 9 | milliardième | Académie 9e éd.: *Un milliardième* | attested |
| 10, 11 | dix-milliardième, cent-milliardième | same rule on attested *milliardième* | productive rule |
| 12+ | — | no Académie *billionième* | not configured |

The ordinal machinery cannot produce them (`dix millième` without hyphen; NTS-33 `deux millionsième`), hence the
static table. Mixed number: Éduscol, *Fractions et nombres décimaux au cycle 3*, p. 13, "2,4 se lira « deux et
quatre dixièmes »" → `mixedFractionSeparator="et"`.

English (OpenStax *Prealgebra 2e* §5.1): `ten-thousandth(s)`, `hundred-thousandth(s)`, "Write 'and' for the decimal
point" → `mixedFractionSeparator="and"`; a zero integer part is not read (*0.05 = five hundredths*).
