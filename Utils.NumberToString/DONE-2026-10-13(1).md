# Utils.NumberToString audit closure — 2026-10-13 (NTS-30A: decimal zero digits, French denominators)

## NTS-30A — zero digits after the decimal separator

NTS-30 recorded (found by NTS-27): "All languages: zero digits after the decimal separator are dropped". This item
is closed; the other NTS-30 items (FI thousands, ES/EU recursive million multiplier, UK/BG/CS/SK and RU scale
agreement, VN zero class, ES currency apocope) stay open in `TODO.md`.

### Defect

`Convert(decimal, …)` reads the decimal part in one of two ways:

- **numerator/suffix branch**: a `<Fraction digits="n">` entry exists for the digit count, or the caller sets
  `DecimalFormatOptions.DecimalSuffix`; the digits are read as one cardinal numerator over the named denominator
  (`21.05` → `twenty-one point five hundredths`). The zero positions are carried by the denominator;
- **digit-by-digit branch**: otherwise, every digit is read in turn (`12.34` → `twaalf komma drie vier`).

In the digit-by-digit branch every digit 0 was lost, leaving an empty slot (and a double space in spaced languages):

| Converter | Input | Before |
|---|---|---|
| NL | `21.05` | `eenentwintig komma  vijf` |
| JA | `21.05` | `二十一点五` |
| ZH | `21.05` | `二十一点五` |
| NL | `Convert(21m, 2)` | `eenentwintig komma` |

### Root cause

```csharp
foreach (char c in digits)
{
    int d = c - '0';
    result.Append(_defaultGroupTable.Digits[1][d].StringValue).Append(Separator);
}
```

The level-1 cardinal table defines `<Digit digit="0" string="" />` in every language: inside an integer, a 0 is an
empty position (`105` is not read *one hundred zero five*). A decimal digit, however, is pronounced explicitly, so the
cardinal position text is the wrong source for it.

### Implementation

Only the digit-by-digit loop in `NumberToStringConverter.Convert(decimal, int, DecimalFormatOptions?, string[])`
changes:

```csharp
foreach (char c in digits)
{
    int d = c - '0';
    string digitText = d == 0
        ? Zero
        : _defaultGroupTable.Digits[1][d].StringValue;
    result.Append(digitText).Append(Separator);
}
```

- a decimal 0 is the converter's standalone `Zero` (the `zero` attribute: `nul`, `零`, `null`, `zero` …);
- digits 1–9 keep their level-1 strings, byte for byte;
- the numerator/suffix branch (`activeSuffix != null`) is not touched, nor are the integer part, the zero padding of
  `mandatoryDecimalDigits` and `OmitZeroDecimals`.

No XML, schema, `<Digit>` entry, public API or language-specific code changes.

### Affected converters

Digit-by-digit for one to three decimals, hence changed for every decimal part containing a 0 (65 converter keys):
AR, BG, CA (and ca-ES, ca-ES-valencia), CS, DA, DE (and de-CH, de-LI), EE, EL, ES, EU, FA, FI, GL, HE, HI, HR, HU,
ID, IT, JA, KO, MS, NB, NL, NO, PL, PT, RO, RU, SK, SV, SW (and SW-KE, SW-TZ), TR, UK, VI/VN, WO, ZH, ZU, their
regional keys, and the SCALE-SHORT/SCALE-LONG/SCALE-SHORT-CYRILLIC base configurations.

Configured fractions for one to three decimals, unchanged on those (9 keys): EN, EN-GB, EN-uk, EN-us, FR, FR-be,
FR-ca, FR-ch, FR-fr. Beyond three decimals EN falls back to the digit-by-digit branch, whose zeros are now read too
(`100.0001` → `one hundred point zero zero zero one`); French names the denominator instead (next section).

### French denominators beyond the thousandths

Review of the PR: in French, beyond the thousandths the denominator is still named and the zeros are not read
(`0,0001` is *un dix-millième*). Before, FR read four or more decimals digit by digit (`cent virgule zéro zéro zéro
et un`, with the level-1 digit text `et un` for 1). The FR configuration (inherited by FR-be and FR-ch) now declares
a `<Fraction>` for every digit count from 4 to the 28-digit decimal precision, built from the long-scale ordinals
of the configuration (`million`, `milliard`, `billion`, `billiard`, `trillion`, `trilliard`, `quadrillion`,
`quadrilliard`) with *dix*/*cent* before them, and spaced like the rest of the FR configuration (`dix millième`, as
`ConvertOrdinal(10000)`):

| Digits | Suffix | Digits | Suffix |
|---|---|---|---|
| 4 | `dix millième(s)` | 15 | `billiardième(s)` |
| 5 | `cent millième(s)` | 18 | `trillionième(s)` |
| 6 | `millionième(s)` | 21 | `trilliardième(s)` |
| 9 | `milliardième(s)` | 24 | `quadrillionième(s)` |
| 12 | `billionième(s)` | 27, 28 | `quadrilliardième(s)`, `dix quadrilliardième(s)` |

(the other counts take *dix*/*cent* before the nearest lower scale ordinal). French therefore never reaches the
digit-by-digit branch, which also removes its `et un` digit reading. The same suffixes name the power-of-ten
denominators of `ConvertFraction` (`2005/10000` → `deux mille cinq dix millièmes`, before `deux mille cinq sur dix
mille`), as they already did for 10, 100 and 1000.

| Converter | Call | Before | After |
|---|---|---|---|
| FR | `0.0001m` | `zéro virgule zéro zéro zéro et un` | `zéro virgule un dix millième` |
| FR | `100.0001m` | `cent virgule zéro zéro zéro et un` | `cent virgule un dix millième` |
| FR | `21.0005m` | `vingt et un virgule zéro zéro zéro cinq` | `vingt et un virgule cinq dix millièmes` |
| FR | `0.000001m` | `zéro virgule zéro zéro zéro zéro zéro et un` | `zéro virgule un millionième` |
| FR | 28 digits `0.0…01m` | `zéro virgule zéro … zéro et un` | `zéro virgule un dix quadrilliardième` |
| FR | `ConvertFraction(2005, 10000)` | `deux mille cinq sur dix mille` | `deux mille cinq dix millièmes` |
| FR-ch | `0.00071m` | `zéro virgule zéro zéro zéro sept et un` | `zéro virgule septante et un cent millièmes` |

Found while checking the scale ordinals and recorded as NTS-33 (not fixed): `ConvertOrdinal` keeps the plural of a
multiplied scale noun (`deux centsième`, `deux millionsième`, `dix milliardsième`). The fraction suffixes are fixed
strings and do not go through that path.

### Dump comparison

Every built-in converter key (74) dumped on master (2fef7acd) and after the change: cardinals, negatives, ordinals for
every variant combination, clock and time, fractions, years, currency amounts, and a decimal matrix (`21.05`, `21.50`,
`21.505`, `21.005`, `0.05`, `-21.05`, `21.57`, `21.5`, 28-digit values, `100.0001`, `1000000.07`; `mandatoryDecimalDigits`
2 and 3; `OmitZeroDecimals`; caller `DecimalSuffix`).

- 1 385 lines changed, all decimal conversions whose rendered digit string contains a 0 in the digit-by-digit
  branch (D 130, E 670, mandatory digits 520, `OmitZeroDecimals` with a non-zero decimal part 65); no changed line
  keeps a double space.
- Byte-identical: every decimal without a zero digit (`21.57`, `21.5`, `0.5`, `1.25`, `2005.5`, `123456.789`,
  `-3.14`), every named-fraction output (EN and FR up to three decimals), every caller-`DecimalSuffix` output, every
  `OmitZeroDecimals` output of a zero decimal part, and all cardinals, ordinals, clock/time, fractions, years and
  currencies.
- French denominators (second dump, against the NTS-30A change alone): 20 lines, only FR, FR-be, FR-ca, FR-ch and
  FR-fr, 4 each (`100.0001`, the two 28-digit values, `ConvertFraction(2005, 10000)`); every other key
  byte-identical.

### Observations (not changed)

- EE reads the decimal 0 with its standalone zero `naneke o` (as for the integer zero); no source on spoken Ewe
  decimals was consulted, the rule is generic.
