# NTS-30C — productive agreement of the generated Conway scale nouns (2026-10-14)

Split out of NTS-30, after NTS-30B. Starting master: `e34229927cd1d7dd22d174d8f1d1b67be23392de`.
Sources: `docs/NTS-08-linguistic-sources.md`, section NTS-30C.

## Root cause

`<ScaleForm scale="…">` is keyed by one exact scale index. `GetScaleWord` looked the index up and otherwise
fell back to `Scale.GetScaleName(groupNumber).ToPlural(group)`; every name `NumberScale` generates from 10^12
(an unbounded series) therefore kept its bare form: RU `два триллион`, UK `два трильйонів` (the `(ів)` suffix has
no *few* form), BG `две трилион`, CS `dva bilion`, `dva biliard`, SK `dva bilión`, `päť biliard`. Listing
`<ScaleForm scale="4">`, `<ScaleForm scale="5">` … cannot cover an unbounded series.

## Generic primitive

- XML: `<GeneratedScaleForm suffix="N" formSelector="…"><Forms><Form key="…" value="…" forceVariants="…" />`
  inside `<NumberScale>`, after the `<ScaleForm>` elements. `suffix` is the index of a `<Suffix>`; the values are
  **suffix fragments**.
- Programmatic: `NumberToStringConverterOptions.GeneratedScaleForms` (`IReadOnlyDictionary<int, GeneratedScaleForm>`)
  and the immutable `GeneratedScaleForm(LexicalFormSet forms, ILexicalFormSelector? selector = null,
  IReadOnlyDictionary<string, ForcedVariantSet>? multiplierForcedVariants = null)`; the converter exposes
  `GeneratedScaleForms` read-only, with the forced variants canonicalized. One cohesive entry type instead of three
  parallel dictionaries. The options clone copies it as is: it holds no word synthesized from the scale, so a
  clone may replace `Scale` and gets the names of the new prefixes.
- Resolution (`ResolveScaleWord`): an exact `ScaleForm` of the scale wins (CS/SK keep their sourced scales 2–3);
  otherwise, for a generated scale, the entry of its suffix: the selector runs **once** on the caller's
  effective variants, the selected fragment is passed to the existing `NumberScale.BuildDynamicName(prefix,
  fragment)` (no generated name is patched afterwards), and the variants forced by that form, if any, are overlaid
  on the caller's query for the multiplier digits only (`ApplyVariantRules` on the unfinalized multiplier
  fragment); otherwise the historical name, byte for byte.
- `baseOn`: entries merge by suffix index (child replaces the same index, other inherited indices kept); a
  duplicate index inside one language is rejected.
- Validation at load/construction: index in `0..Suffixes.Count-1` (XSD `nonNegativeInteger`), the scale must
  name a generated scale with that suffix, no null entry, non-empty forms and fragments, forced keys among the
  forms, forced dimensions/values declared by the language (`UNTS006`), and every key returned by the selector for
  the multipliers 1..min(group divisor − 1, 9999) under the language defaults (`UNTS007`); a key reachable only
  under a caller variant still fails deterministically at conversion (`UNTS007`).

## NumberScale integration

`NumberScale.TryGetDynamicScaleInfo(int scale, out long prefix, out int suffixIndex)` (internal) is now the only
place mapping a scale index to its Conway prefix value and suffix index (`scale − StaticValues.Count +
StartIndex`, `DivRem` by the suffix count). `GetScaleName` calls it (same negative-index and no-suffix errors),
and so does the converter; no arithmetic is duplicated. Conversion does an O(1) array lookup by suffix index; no
per-scale dictionary or cache of generated names is built.

## Review follow-up (PR #638): forced variants through the whole group pipeline

Review (and the Codex thread on `NumberToStringConverter.cs`): the first version applied the forced variants
only to the global variant rules of the multiplier digits; the `group(N)` triggers, the `onScale` variant rules
and the `groupWithScale(N)` triggers still received the caller's query, and the whole-number passes with the
caller's query could rewrite the forced multiplier. Fixed:

- `ConvertRaw` resolves the scale word first (selector once, caller query), computes the group query (forced
  over caller; the caller's query unchanged when nothing is forced) and passes it to every local pass of the
  group: `group(N)` triggers, the variant rules of the multiplier, the scale-scoped (`onScale`) variant rules,
  the `groupWithScale(N)` triggers.
- A group rendered with forced variants is shielded from the whole-number passes made with the caller's
  query (global variant rules and `end` triggers in the cardinal, the cardinal fragment and the generic ordinal
  path): it is replaced by a private-use token for those passes and restored, so a caller value cannot
  overwrite a forced value; a pass that destroys a token throws `InvalidOperationException`. The rest of the
  number still follows the caller's variants. Languages without generated forms allocate nothing.
- Tests (written first, red on `dc04cea2`): `Synthetic_ForcedVariantsReachScaleScopedVariantRules`,
  `Synthetic_ForcedVariantsReachGroupTriggers`, `Synthetic_ForcedVariantsAreNotReprocessedWithTheCallerQuery`.
