# Utils.NumberToString audit closures — 2026-10-09 (NTS-21)

NTS-21 closes the Wolof large-number gap left by NTS-19 (`maxNumber="999999"`). Wolof cardinals are now
unbounded: the attested loans `milyoŋ` and `milyaar` anchor a long-scale Conway-Guy-Wechsler extension spelled
with Wolof letter values. Sources are in `docs/NTS-08-linguistic-sources.md`, section "NTS-21".

## Evidence levels

### Attested

| Value | Form | Source |
|---|---|---|
| 10^6 | `milyoŋ` (`benn milyoŋ`) | Boston University, The 200 Word Project, "Woññi (Numbers)": `Fukki Téémééri Junni / Benn Milyoŋ` (re-read for NTS-21); Guérin, Wolof university teaching material and Senegalese Twisted as given by the NTS-21 task |
| 10^9 | `milyaar` (`benn milyaar`) | Guérin, Wolof university teaching material and Senegalese Twisted, as given by the NTS-21 task (not reachable during NTS-21; taken as the task's authoritative anchors) |

`milyoŋ` / `milyaar` are kept as written: not `milyon`, `million`, `miliyar`. The configuration's former unused
suffix `milyon` is gone.

### Productive library convention

`bilyoŋ`, `bilyaar`, `trilyoŋ`, `trilyaar`, … and the whole Conway-Wechsler continuation. Because the attested
pair is million + milliard, the extension follows the **long scale**: 10^(6n) is the `-yoŋ` name of Conway index n,
10^(6n+3) its `-yaar` name. Wolof has adopted the `milyoŋ` / `milyaar` family; the library extends it productively
with Conway-Guy-Wechsler on the long scale using Wolof-compatible spellings. Generated higher names are a library
generation convention, not a claim that every generated form is independently attested in Wolof usage.

## Engine primitive: `suffixSeparator`

`NumberScale` had a single `groupSeparator`, inserted both between Conway groups and before the suffix. The Wolof
target needs `li` between groups and `l` before the suffix (`mi + l + yoŋ`, `mi + li + ni + l + yoŋ`); no
configuration of the existing attributes produced it (`l` alone gives `milnilyoŋ`, `li` alone `miliyoŋ`, `l` with
voidGroup `ini` fixes only empty groups: `miltrilyoŋ`). User decision: a new optional attribute.

- XML: `<NumberScale suffixSeparator="…">` (XSD documented), merged through `baseOn` like `groupSeparator`; an
  explicit empty value joins the suffix directly.
- API (additive): `NumberScale.SuffixSeparator { get; init; }`, `NumberScaleType.SuffixSeparator`,
  `NumberScaleXmlModel.SuffixSeparator`. The constructor signature is unchanged.
- `BuildDynamicName` appends `SuffixSeparator ?? GroupSeparator` after the last group: same algorithm, no other
  language sets the attribute, so their output is unchanged.

## Multipliers

Audit of the NTS-19 rule: the connective `-i` is a genitival linker between a numeral and the counted noun (Gaye
1980), carried by the last element of the multiplier of `téeméer` and `junni` (Boston University
`fukki téeméeri junni`). `milyoŋ`, `milyaar` and the higher names are nouns in the same position, so their
multipliers take it too; one is the bare attested `benn milyoŋ` / `benn milyaar`:

| Value | Form |
|---|---|
| 1 000 000 | benn milyoŋ (attested) |
| 1 000 000 000 | benn milyaar (attested) |
| 2 000 000 | ñaari milyoŋ |
| 2 000 000 000 | ñaari milyaar |
| 1 000 000 000 000 | benn bilyoŋ |
| 1 000 001 | benn milyoŋ ak benn |
| 1 001 000 | benn milyoŋ ak junni |
| 1 001 001 | benn milyoŋ ak junni ak benn |
| 21 000 000 | ñaar fukk ak benni milyoŋ |
| 200 000 000 | ñaari téeméeri milyoŋ |

Only the two `benn` anchors are attested; the other multipliers apply the NTS-19 rule productively. The `junni`
rules are scale-specific replacements (one scale name); an unbounded set of names cannot be listed, so the rule is a
`<Trigger executeAt="groupWithScale">` whose two regular expressions add `-i` to the last word before a name ending
in `yoŋ` or `yaar` (`benn` only when it is not the whole multiplier). A test checks that every multiplier 1–999 of
`milyoŋ`, `milyaar` and `bilyoŋ` equals the multiplier of `junni`.

## Ordinals

Unchanged: the ordinal domain stays 1–999 999 minus the NTS-16/NTS-19 rejections. The cardinals now reach the
millions, but no consulted source exemplifies a Wolof ordinal above the thousands, so `WolofOrdinalLanguageSpecifics`
rejects every value from a million with `NotSupportedException` (before NTS-21, `maxNumber` rejected them with
`InvalidOperationException`). `NumberToStringNts16Tests.WolofGuard_RejectsZeroAndRoundThousands_LetsOtherValuesThrough`
no longer lists `long.MaxValue` among the accepted values (it is now rejected by design).

## Validation

- Before/after dump of all 74 configured cultures (scale names, powers of ten, cardinals 0–2100, random
  cardinals and negatives, ordinals, ClockTime, decimals, fractions, years): only `WO` changes. No Wolof regional
  culture exists.
- Wolof 0–999 999 (cardinals, ordinals, negatives): byte-identical.
- ClockTime unchanged (still unsupported for WO).
- New tests: `NumberToStringNts21Tests` and the Wolof feature scenarios "Cardinal numbers from a million" and
  "Ordinals from a million are not supported".
