# Utils.NumberToString audit closure — 2026-10-11 (NTS-31, cardinal part)

## NTS-31 — Dutch long-scale cardinal names (cardinal part closed)

Dutch stopped at `maxNumber="999999"` with only `duizend` and an unused `miljoen` suffix. Under the repository's
Conway rule (`AGENTS.md`, root `README.md`: establish the language's base pattern and orthography, then continue it
productively with the shared Conway machinery), the Dutch long scale is now configured on `SCALE-LONG`. The
expectations were written in `Dutch.feature` and run red (29 cardinal rows) before the configuration change.
Sources: section "NTS-31" of `docs/NTS-08-linguistic-sources.md`.

### Dutch model

- Long scale, suffix cycle `joen` / `jard` (invariable: exact numerals take the singular, *twee miljoen*).
- Conway tables inherited unchanged from `SCALE-LONG`: Scale0 `mi, bi, tri, quadri, quinti, sexti, septi, octi,
  noni` (Latin, not the Swedish `kvadri/kvinti/okti`), strict NTS-24 units/tens/hundreds, linking consonants,
  `a → i` before `-illi-`, grouped indices.
- Junction: `l` before the suffix (`mi + l + joen`). The engine joins the Conway groups of an index ≥ 1000 with
  `groupSeparator` and the last group to the suffix with `suffixSeparator` (default: `groupSeparator`). NL sets only
  `suffixSeparator="l"` and inherits the `-illi-` joint (`lli`), so the two settings give the same output below index
  1000 and differ only from 10^6000. At 10^6000 the selected strict Conway continuation gives *milliniljoen*
  (*milli + ni + l + joen*, English *millinillion*). The secondary Dutch table consulted instead lists the traditional
  form *milliljoen*; this known divergence between two extension systems is intentional and is not used as an
  exception to the repository-wide Conway construction (`AGENTS.md`). `groupSeparator="l"` (the Swedish choice)
  would give *milniljoen*, which is neither form. Same pattern as Wolof (`groupSeparator="li"`,
  `suffixSeparator="l"`).
- *duizend* drops *een* (existing NTS-08 replacement); *een miljoen*, *een miljard*, *een biljoen* keep it (no
  replacement added). Groups are separated by a space, without *en*; the inherited `SCALE-LONG` `groupSeparator=","`
  is overridden by NL's `groupSeparator=""` on `<Language>`.

### Configuration (`NumberConvertionConfiguration.NL.xml`)

- `baseOn="SCALE-LONG"` added; `maxNumber="999999"` removed.
- `<NumberScale firstLetterUpperCase="false" suffixSeparator="l">`, static names `""` and `duizend`, suffixes
  `joen` and `jard`; no prefix table duplicated.
- Replacements unchanged (`een duizend` → `duizend`, ` duizend` → `duizend`, `tweeen`/`drieen` diaeresis).
- The ordinal comment now points to the explicit guard.

### Ordinals (intentionally unchanged)

`DutchOrdinalLanguageSpecifics` already guarded `number < 1 000 000` explicitly (not through `maxNumber`); only its
documentation changed. `ConvertOrdinal(999 999)` stays *negenhonderdnegenennegentigduizend
negenhonderdnegenennegentigste*; 1 000 000, 1 000 001, 2 000 000, 10^9 and `long.MaxValue` still throw
`NotSupportedException`; beyond `long` the engine's general ordinal contract throws `ArgumentOutOfRangeException`
(unchanged, as for every language). The remaining part of NTS-31 (ordinals from a million) stays open.

### Before/after comparison

Dump of every converter before (master 65347b34) and after: **19 lines changed, all NL cardinals**: the 18 sampled
cardinals from 1 000 000 upward and the negative −1 000 000 (*min een miljoen*), from `ArgumentOutOfRangeException`
to their wording. Every NL cardinal ≤ 999 999, every ordinal, clock, decimal, fraction, year and currency output, and
every other converter are byte-identical.
