# Utils.NumberToString audit closures — 2026-10-06 (1)

NTS-14 is closed: each of its four independent families is fixed or explicitly decided, test-first
(the scenarios and engine tests were run red before every functional change). Sources and decisions
are recorded in `docs/NTS-08-linguistic-sources.md` ("NTS-14"). A before/after dump of every
built-in language (cardinals and ordinals 0–2100, thousands multiples, millions to 10^18, every
variant value, five-minute clock times) was compared after each commit:

| Commit | Changed lines |
|---|---|
| IT configuration | 48 — IT cardinals ≥ 1 000 000 only |
| Scale lexical forms engine | 0 |
| AR configuration | 849 — AR cardinals ≥ 1000 only |
| Ordinal replacements engine | 0 |
| HE configuration | 362 — HE ordinals, default and standalone queries only |
| Zero ordinals | 52 — ordinal of zero in RU, DE (+ DE-ch/de-LI), CA (+ ca-ES, CA-valencia), WO, EE only |

## Engine additions

- **Scale lexical forms** — `<NumberScale><ScaleForm scale formSelector>`: the existing
  `ILexicalFormSelector` / `LexicalFormSet` infrastructure (time units) now also chooses the form of
  a scale noun from its group multiplier (`LexicalFormContext.Value`), with the effective variants.
  `NumberScale.GetScaleName` is unchanged (base name); the converter builds per-scale definitions
  once (synthesized singular/plural overridden by the configured forms, default selector when none),
  so no selector is resolved and nothing is built during conversion. Unknown key → `UNTS007`;
  unnameable index, null entry or duplicate scale → rejected at load; `baseOn` merges by scale;
  options clone and snapshot covered. Tests: `NumberToStringScaleFormTests` (19) + Security snapshot.
- **Ordinal-only replacements** — `<Replacement>` in `<Ordinals>` and in an ordinal `<Variant>`,
  reusing `ReplacementRule`/`ReplacementScope` and the cardinal scope implementation. Pipeline:
  whole-number exception → `ConvertRaw` → cardinal variant rules → ordinal replacements (base, then
  selected variant, including an injected default) → exact `<Ordinal>` → `OrdinalStem` →
  `removeTrailing` → suffix/prefix. `onScale`/`onValue` and missing `newValue` rejected; base list
  replaced by a derived language that declares one (as the cardinal `Replacements`).
  `OrdinalVariantRule` gains `Replacements` through a new constructor overload; the historical
  constructor chains to it. Tests: `NumberToStringOrdinalReplacementTests` (25) + Security snapshot.
- **Zero guard** — `ZeroOrdinalUnsupportedLanguageSpecifics`, a shared opt-in plugin: chosen over a
  declarative `<UnsupportedOrdinal>` because it needs no model, XSD, options or `baseOn` surface for
  three languages, and leaves the NTS-12 contract untouched elsewhere.

## The four families

- **IT millions and above** — existing mechanisms only: scale `groupSeparator="li"` and lower case
  (`milione`, `miliardo`, `bilione`, `biliardo`, `trilione`), `groupConnector="e"` with the soldering
  replacements now removing it after `mille`/`-mila` (`milleuno`, `duemilauno` unchanged), and
  `un` before a single scale noun (`ventuno milioni` keeps `ventuno`). A connector-per-scale
  primitive was not needed: two existing replacements were retargeted, no cascade was added.
  Italian ordinals ≥ 1 000 000 still fail closed, now tracked by **NTS-17**.
- **AR thousands** — `ArabicScaleLexicalFormSelector` (keys from the last number written: 0–1
  singular, 2 dual, 3–10 plural, 11–99 singular accusative) with the words in XML, plus `onScale`
  replacements for the multiplier text (`ألف`, `ألفان`, `مائة وألف`, `مائتا ألف`). The feminine
  unit-and-tens compound rules are restricted to the units group, so the multiplier keeps the
  masculine agreement of ألف. Contract: standalone nominative (`ألفان`). Tests: `Arabic.feature`,
  `NumberToStringArabicThousandsTests` (selector matrix + mechanical sweep).
- **HE compound ordinals ending in a teen** — nine `EndsWith` ordinal replacements in the
  standalone ordinal variant; no plugin, no rebuilt cardinal. Default ordinals ending in 11–19 now
  equal the zachar ordinals (mechanical sweep to 99 999); the cardinal, nekeva and zachar are
  unchanged.
- **Zero ordinals** — RU `нулевой` and DE `nullte` as declined `OrdinalException value="0"`; CA (and
  CA-valencia), WO and EE fail closed through the zero guard for lack of any source.

## Opened

- **NTS-16** — Wolof (`-ël` vs attested `-eel`/`-éél`) and Ewe (`etsõ` prefix vs attested `-lia`
  suffix) ordinal formation, and their zero cardinals, are unsourced.
- **NTS-17** — Italian ordinals of one million and above.

NTS-15 is untouched.

## Test corrections during the work

- The two new Arabic scenarios were first committed without their `Given I use the "AR" number
  converter` step and failed for that reason; the step was added and the scenarios were verified
  red against the previous configuration before the fix (34 assertion failures).
- The ordinal-replacement word-rule test first targeted a hyphenated word, which
  `ApplyOrdinalTransform` splits; it was corrected to a plain word.
