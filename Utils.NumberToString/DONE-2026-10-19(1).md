# NTS-42 — audit of the UK, CS and SK fraction closures left by NTS-40/41 (2026-10-19)

Opened by NTS-40/41 (`DONE-2026-10-16(1).md`). Starting master: `4cd45b72` (NTS-43, #647). Audit-first: each of the six
families was reproduced separately, located in the pipeline, and qualified. **No production code changed**: no engine,
plugin, XML, XSD or public API change; the audit adds tests that pin every closure and its open neighbours.

## Where the readings are built

```text
ConvertFraction(n, d, variants)
  → BuildFractionText                       (generic engine, NumberToStringConverter)
      1. named power-of-ten <Fractions>     (not configured for UK, CS, SK)
      2. IFractionLanguageSpecifics.TryGetFractionDenominator(n, d, variants)
           false → NotSupportedException    (the only closure path, no language test in the engine)
           reading.NumeratorText → ApplyRawAdjustment(text) + " " + reading.Text   (NTS-40 oblique numerators)
           otherwise → BuildCardinalFragment(n, forced ⊕ variants) + " " + reading.Text
  → FinalizePhrase (sign, finalization once)
```

The engine has no special path for zero, a case, a slash reading or a scale: zero and the caller's case reach the
plugin like any other numerator (test `E_ZeroReachesThePluginWithTheCase`). Every NTS-42 family is decided inside the
language plugin classes — `CzechOrdinalLanguageSpecifics`, `SlovakOrdinalLanguageSpecifics`,
`UkrainianOrdinalLanguageSpecifics` and their `*.FractionCases.cs` parts. These are public classes of this repository
(not external private plugins); their declined-cardinal builders are `private` to each class, as NTS-40/41 designed them.

## Reproduction (scratch probe over every case × gender, 1 949 probe lines)

No reading of the six families is silently wrong: every one is either a sourced reading or the engine's
`NotSupportedException`; no other exception type, no empty or malformed text.

## Decisions

| family | reproduced? | responsible layer | decision |
|---|---|---|---|
| A — CS *jedna* in a compound | yes, as a deliberate closure | CS plugin (`DeclineCardinal`/`AppendDeclinedGroup`) | **contract insufficient**: the IJP gives only the nominative (*dvacet jeden žák* / *dvacet jedna žáků*); no gender/case is lost by the engine (the numerator's gender is fraction-local, the caller's is ignored by design) |
| B — CS multiplier ending in one | yes, as a deliberate closure | CS plugin (`AppendDeclinedScale`) | **contract insufficient**: no source gives the gender of a compound-final *jedna* before *tisíc*/*milion* outside the nominative; *miliarda* (feminine) is closed by the same rule as A, so no scale is special-cased |
| C — SK bare *jeden* | yes, as a deliberate closure | SK plugin (`DeclineLastComponent`) | **contract insufficient**: Morfológia 326 covers the *-jeden* compounds, not *sto jeden*; the plugin already distinguishes a bare final *jeden* from a compound and from a coefficient (the *číslom* reading) — no new notion needed |
| D — *lomeno*/*lomené* oblique | yes, as a deliberate closure | CS/SK plugins (`TryGetFractionDenominator`) | **contract insufficient**: no source declines the slash phrase, whose denominator is already an instrumental; there is no available variant the selector ignores |
| E — zero oblique | yes, as a deliberate closure | UK/CS/SK plugins | **contract insufficient**: no source declines *нуль*/*nula* with a fraction; zero does not bypass any engine machinery (the engine forwards it with the case) |
| F — ≥ 10^12 | yes, as a deliberate bound | CS/SK/UK builders (`MaxDeclinedNumber`, `MaxDeclinedNumerator`) | **deferred / dependency**: see below |

None of A–E has a defect in the generic engine to fix; opening any of them needs a linguistic source, not code. None
was changed on a linguistic supposition.

### F — the 10^12 bound

- The builders spell and decline *tisíc*, *milion*, *miliarda* (and UK *тисяча*, *мільйон*, *мільярд*) from their own
  paradigm tables and stop at `999 999 999 999`. From 10^12 the names are **generated** by the engine's single
  Conway-Guy-Wechsler machinery (`NumberScale` + `<GeneratedScaleForm>`, NTS-30C), which only provides the count-agreement
  forms of the nominative (*dva biliony*, *pět bilionů*, *dvě biliardy*). A plugin has no access to these generated names
  or to their oblique forms.
- Opening F would need either a second spelling of the generated names inside the plugins (a duplicate of the Conway
  machinery — excluded) or a **generic** way for the engine to supply a generated scale noun in a requested case to a
  fraction plugin (a new engine/contract capability, possibly XML case forms on `<GeneratedScaleForm>`): a design
  decision outside NTS-42, to be specified before any code.
- From 10^24 the CS/SK names also depend on **NTS-36** (*quadrilion* → *kvadrilion*): declining them before NTS-36 would
  decline the wrong spelling.
- The current behaviour is the right fail-closed one: a deterministic `NotSupportedException` at an explicit bound, the
  nominative numerators reading the generated cardinal unchanged (`F_NominativeNumerators_UseTheGeneratedScales`).
