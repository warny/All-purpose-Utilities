# Utils.NumberToString — NTS-04 closure: constituent-local ForcedVariants

Closes NTS-04, previously deferred in `DONE-2026-08-21(1).md` (2026-08-21,
commit `ee923b3fdf95925170c65d6b5798250c366b4e04`-adjacent audit).

## Why NTS-04 was reopened

The 2026-08-21 audit ("Conclusion A — no concrete defect") was correct for the
evidence available at the time: no built-in language/API combination then
demonstrated incorrect output. It is not being rewritten as "wrong" — it was a
proof-first audit that found no counterexample yet.

A later targeted test removed the caller's explicit `gender=feminin` workaround
from the French time-unit conversion and exposed a concrete defect:

```
fr.Convert(new TimeSpan(1, 0, 0))       -> "un heure"          (expected "une heure")
fr.Convert(TimeSpan.FromHours(21))      -> "vingt et un heures" (expected "vingt et une heures")
```

"heure"/"minute"/"seconde" are intrinsically feminine in French. The converter
required the caller to know this and pass `gender=feminin` explicitly
(`Convert_TimeSpan_FR_OneHour`, `NumberToStringConverterTimeAndNewLangTests.cs`).
The same structural problem generalizes to any configured lexical constituent
that owns intrinsic grammatical constraints on the numeric fragment it governs
— demonstrated concretely with currency: a masculine unit ("euro") and a
feminine unit ("livre") must render correctly through the same French
converter without the caller supplying gender at all, and a currency's main
unit and subunit must be able to require *different* local grammar in the same
phrase (e.g. `21.21` with a masculine unit and a feminine subunit).

## Resolution — `ForcedVariantSet`

NTS-04 is now implemented as a single general mechanism, not a TimeUnit-only
fix:

- `ForcedVariantSet` (`Utils.NumberToString/ForcedVariantSet.cs`) is one
  reusable, immutable dimension→value representation, built on the existing
  `VariantConstraintSet` (no second variant engine).
- The effective variant query for a numeric fragment governed by a configured
  constituent is `language defaults < caller-supplied variants < constituent
  ForcedVariants`, merged per dimension via `ForcedVariantSet.Overlay`, which
  is the single shared fusion primitive used by every consumer (`FormatTimeUnit`,
  `ConvertCurrency`, `BuildFractionText`, and the inline decimal-fraction path).
  No consumer re-implements the merge.
- ForcedVariants are strictly local: they affect only the fragment built by
  the constituent that declares them, never leak to sibling fragments in the
  same composite phrase, another call, or the converter's global defaults.
  Ordinary `Convert(1)`/`Convert(21)` remain masculine in French.
- Semantic validation (`NumberToStringConverter.ValidateForcedVariants`) is
  shared by every consumer, reuses the converter's declared
  `VariantDimensions`, and runs once — at converter construction for
  configuration-owned constituents (time units, fraction terms), and once per
  call, before any fragment is rendered, for `CurrencyDefinition` (which is
  supplied by the caller and not owned by the converter at construction).
- Public API stayed additive: `NumberToStringConverterOptions.TimeUnits`
  (existing 3-field tuple) and `CurrencyDefinition`'s existing properties are
  unchanged; new properties (`TimeUnitForcedVariants`, `FractionForcedVariants`,
  `CurrencyDefinition.UnitForcedVariants`/`SubunitForcedVariants`) are additive
  and default to `ForcedVariantSet.Empty` (identical to pre-NTS-04 behavior).
  Internally, the converter converges `TimeUnits` + `TimeUnitForcedVariants`
  into one internal `TimeUnitDefinition` record — one runtime representation,
  two backward-compatible public views.
- XML: a single consistent `forceVariants="dimension=value[,dimension2=value2]"`
  attribute, reusing the existing `dimension=value` vocabulary, added to
  `<Unit>` (TimeUnits) and `<Fraction>` in the XSD. `baseOn` inheritance is
  unchanged: both sections already merge as whole blocks, so a child that
  doesn't redeclare `<TimeUnits>`/`<Fractions>` inherits the parent's
  `forceVariants` too, and a child that redeclares the section must repeat them
  — consistent with existing `Count1Form` semantics.
- No culture switches, no word-based heuristics (`endsWith`, literal word
  comparisons), no new phrase-level replacement pass, no change to the global
  French `gender` dimension order (masculine stays the default).

## Constituent audit matrix (supersedes the 2026-08-21 matrix for NTS-04 purposes)

| Constituent | Governs a numeric fragment? | Class | Resolution |
| --- | --- | --- | --- |
| Time units (hour/minute/second) | Yes | A | `TimeUnitForcedVariants`; FR hour/minute/second now declare `forceVariants="gender=feminin"` |
| Currency main unit | Yes | A | `CurrencyDefinition.UnitForcedVariants` |
| Currency subunit | Yes | A | `CurrencyDefinition.SubunitForcedVariants`, independent of the unit |
| Fraction denominator term (e.g. "dixième(s)") | Yes (numerator) | A | `FractionForcedVariants`; no built-in language currently needs it, covered by a synthetic test |
| Currency connector ("and"/"et") | No — literal joiner | B | Unchanged |
| Fraction separator ("/", "sur") | No — literal joiner, non-decimal path | B | Unchanged |
| Multiplicative named forms ("une fois") | No — complete literal lexical forms | B | Unchanged |
| Multiplicative unnamed suffix | Already reaches the ordinary `BuildVariantQuery`/`ApplyVariantRules` pipeline | C | No config-level forcing exists to migrate; nothing to add |
| Ordinal suffix/word rules/exceptions | Governs the ordinal itself, via a dedicated mechanism | C | `OrdinalVariantRule`/`OrdinalVariants`, not duplicated |
| Scale/group connectors, scale names | Already variant-aware via `ReplacementRule.OnScale`/scale-mode `VariantRule` | C | Unchanged |
| Month names | No — sourced from `CultureInfo`, not converter-configured | B | Unchanged |
| Date-time connector, date pattern literals | No — literal joiners | B | Unchanged |
| `DateFirstDay`/`DateFirstCardinalDay` | Complete literal override, not a built fragment | B | Unchanged |

Every constituent category is now either A (ForcedVariants-capable), B (does
not govern a numeric fragment), or C (already fully served by an existing,
non-duplicated mechanism). No open "governs a number but cannot force its
grammar" gap remains.

## Regression coverage

`UtilsTest/Mathematics/Numbers/NumberToStringConverterForcedVariantsTests.cs`
(new) covers: the red-test-first FR time-unit matrix (1 and 21, hour/minute/
second), the composite `TimeOnly` proof, forced-wins-over-contradictory-caller,
FR cardinal non-regression, EN/DE non-regression, sequential anti-leak,
masculine/feminine currency with the same converter, independent unit/subunit
forcing in one phrase, a synthetic fraction term, an engine-level two-dimension
proof independent of French data, a no-leak proof across differently
constrained constituents, immutability/snapshot, `FromCulture("FR")`
round-trip, and deterministic rejection of malformed/unknown/duplicate forced
variants (error codes `UNTS004`/`UNTS005`/`UNTS006`).
`NumberToStringCompositeFinalizationTests.cs` gained a currency test proving a
phrase with two different local `ForcedVariants` queries is still finalized
exactly once (NTS-03 preserved).
