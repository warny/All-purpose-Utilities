# Utils.NumberToString audit closures — 2026-10-07 (5)

NTS-23 (Ewe scales above the million) is closed. Ewe large-number naming now follows the
Conway-Wechsler short scale, anchored by sourced `miliɔn`, `biliɔn` and `triliɔn` forms and productively
extended to higher `-liɔn` names. Configuration, tests and documentation only: no engine, API or XSD
change. Decisions are recorded in `docs/NTS-08-linguistic-sources.md`, section "NTS-23". Opened NTS-24.

## Premises

The preceding linguistic audit is taken as validated and was not redone: `akpe` = 10^3,
`miliɔn` = 10^6, `biliɔn` = 10^9, `triliɔn` = 10^12 (short scale, CLDR compact patterns). Project
decision: higher names follow the Conway-Wechsler short scale productively.

## Mechanism

- `EE` declares `baseOn="SCALE-SHORT"` and inherits the four Conway-Wechsler prefix tables; it overrides
  the static names (`""`, `akpe`), `groupSeparator="li"` and `<Suffix>ɔn</Suffix>`. Each name is
  prefix + `li` + `ɔn`; the static `miliɔn` of NTS-22 is now generated identically. The shared
  tables are reused, not duplicated, and `SCALE-SHORT` is unchanged.
- Effective `startIndex` 0, determined from the engine's behaviour: with two static names, scale 2 is
  Conway n = 1 (`GetScaleName(2..6)` = `miliɔn`, `biliɔn`, `triliɔn`, `quadriliɔn`, `quintiliɔn`).
- Precedent: SW also inherits SCALE-SHORT with its own suffix (`lioni`).

## Domain

`NumberScale.IsUnbounded` is true and `CanNameGroup` succeeds for every index, so `maxNumber` is removed,
the policy of EN, ID, SW and TR. Cardinals accept any `BigInteger` (10^303 = `centiliɔn ɖeka`); ordinals
keep the engine-wide `long` limit (`ConvertOrdinal(10^18)` = `quintiliɔn ɖekalia`, 10^21 rejected with
`ArgumentOutOfRangeException` as in every language).

## Composition and ordinals

Unchanged rules: scale noun first, standalone-cardinal multiplier (`biliɔn blaeve vɔ ɖekɛ`,
`triliɔn alafa eve`, `quadriliɔn alafa asieke blaasieke vɔ asieke`); `kple` before a lower group below
100 (`biliɔn ɖeka kple miliɔn ɖeka`); ordinals `-lia` on the last numeral element (`biliɔn ɖekalia`,
`quadriliɔn ɖekalia`), never on the scale noun; no `<Groups onScale>`, no `<OrdinalScale>`.

## Documented, not produced

- `akpe akpe`: historical/traditional formation with variable glosses in the sources; no
  `traditional|modern` variant.
- CLDR RBNF (10^9 `miliɔn akpe`, 10^12 `biliɔn`): divergent, not combined with the retained system.
- `kpakple`: minimal search for a second strong source using it as a numeral connector found none. The
  Biblica Ewe Bible has 99 occurrences, all a nominal "and" between noun phrases; the grammar literature
  describes it as an additive linker of nominal groups. CLDR RBNF's `kpakple` remains an uncorroborated
  divergent rule; `groupConnector="kple"`, `groupConnectorThreshold="100"` kept; no architecture change
  needed.

## Finding: NTS-24

Checked against strict Conway-Guy-Wechsler, the target convention, the SCALE-SHORT names from 10^36
fall into two groups:

| Scale | SCALE-SHORT | Strict Conway | Verdict |
|---:|---|---|---|
| 12 (10^36) | `unidecillion` | `undecillion` | table error (`uni` → `un`), NTS-24 |
| 16 (10^48) | `quinquadecillion` | `quinquadecillion` | correct Conway (dictionary `quindecillion`) |
| 17 (10^51) | `sedecillion` | `sedecillion` | correct Conway (dictionary `sexdecillion`) |
| 20 (10^60) | `novendecillion` | `novendecillion` | correct Conway (dictionary `novemdecillion`) |
| 21 (10^63) | `vingtillion` | `vigintillion` | table error (`vingti` → `viginti`), NTS-24 |

The three Conway forms are intended and asserted in the reference table test. The two errors (plus
`trigintallion` and `unillinillion`, to check with them) are left unchanged in this PR, since a fix
changes EN, ID, SW, TR and EE, and are pinned by
`NumberScaleContractTests.ShortScale_ConwayWechsler_KnownTableErrors`; EE inherits them
(`unideciliɔn`, `vingtiliɔn`).
