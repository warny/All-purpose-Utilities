# NTS-43 — `AdjustFunction` runs after the cardinal morphology (2026-10-19)

Found by the NTS-40 review (PR #646). Starting master: `af04dabd` (NTS-40/41, #646).

## Defect

`NumberToStringConverterOptions.AdjustFunction` was documented as a final transformation, but the cardinal pipeline
ran it **before** the morphology:

```text
old:  raw → adjustment → morphology (variant rules) → end triggers → finalization → minus
new:  raw → morphology (variant rules) → adjustment → end triggers → finalization → minus
```

A textual `<Variant><Replacement>` therefore looked for text the adjustment had already rewritten: with
`AdjustFunction = s => s.ToUpperInvariant()`, the UK feminine `два → дві` gave `ДВА` (and the 2/3 numerator
`ДВА третіх`), CS/SK `dva → dvě/dve` gave `DVA`, FR `un → une` gave `UN`, ES `veintiuno → veintiuna` gave
`VEINTIUNO`, FI `kaksi → kahta` gave `KAKSI`, and so on for every language whose morphology is a textual replacement.

## Audit of the `AdjustFunction` application sites (`af04dabd`)

| site | before | after NTS-43 |
|---|---|---|
| `ConvertCardinalUnchecked` (top-level `Convert(BigInteger, …)`, zero included) | **wrong**: adjust → variants + end triggers | fixed |
| `BuildCardinalFragment(BigInteger, query)` (every composite numeric fragment) | **wrong**: adjust → variants + end triggers | fixed |
| `BuildOrdinalFragment` | correct: ordinal morphology/word rules → adjust → end triggers | unchanged |
| `ConvertMultiplicative` | correct: variants → adjust → end triggers | unchanged order, now through the shared helper |
| `BuildFractionText`, plugin-supplied `NumeratorText` (NTS-40) | correct: declined by the plugin → adjust | unchanged |
| `Convert(decimal, …)` phrase adjustment (`FinalizePhrase(ApplyRawAdjustment(text))`) | after its fragments' morphology | intentionally unchanged (scope, not order) |
| `Convert(Number)` phrase adjustment | after its fragments' morphology | intentionally unchanged (scope, not order) |

The cardinal and fragment pipelines now share one private helper, `ApplyCardinalPostProcessing`, also used by
`ConvertMultiplicative` (same three passes, previously written out by hand). It never finalizes and never adds a sign;
the composites still finalize their complete phrase exactly once. The adjustment scope (per numeric fragment, plus the
historical phrase adjustment of decimals and rationals) and the call counts are unchanged.

## Final pipelines

| conversion | pipeline |
|---|---|
| top-level cardinal | `ConvertRaw` → whole-number variant rules → `AdjustFunction` → end triggers → `FinalizeWriting` → minus |
| cardinal fragment | `ConvertRaw` (constituent forced variants overlaid on the caller query) → variant rules → `AdjustFunction` → end triggers |
| ordinal | plugin / exceptions / composition / cardinal + variant rules → ordinal replacements and word rules → `AdjustFunction` → end triggers → `FinalizeWriting` → prefix → minus |
| multiplicative | named form, or `ConvertRaw` + suffix → variant rules → `AdjustFunction` → end triggers → `FinalizeWriting` → minus |
| plugin-supplied oblique numerator | declined by the plugin → `AdjustFunction` (no variant rules, no end triggers) |

## Shielding

The scale groups whose multiplier was rendered under forced variants (exact `<ScaleForm forceVariants>`, NTS-30G;
`<GeneratedScaleForm forceVariants>`, NTS-30C) stay out of both caller passes: `ApplyShielded` wraps the variant
rules, then, separately, the end triggers; the adjustment runs between them on the plain text and sees the forced
group as ordinary text. The fix makes the shield matter for the variant pass in an adjusted converter: before,
an uppercase adjustment made the caller's rules unmatchable anyway; now they run on the raw text, and the shield keeps
ES feminine `500 000 000` at `QUINIENTOS MILLONES` (not `QUINIENTAS`), CS feminine `2000` at `DVA TISÍCE`, CS masculine
`2·10¹⁵` at `DVĚ BILIARDY`. The end-trigger shielding is the established one: an adjustment that rewrites the group
itself (uppercasing) makes it unlocatable, as `ApplyShielded` documented before NTS-43, and the test
`ScaleForcedVariants_EndTriggerSeesAdjustedTextWithEstablishedShielding` pins both cases.

## Tests

- `CompositeConversion_AdjustFunctionRunsBeforeVariantRules` pinned the defect; replaced by
  `CompositeConversion_FragmentRunsVariantRulesThenAdjustFunctionThenEndTriggers` (variant `two → VARIANT`, adjustment
  `VARIANT → ADJUSTED`, end trigger `ADJUSTED → TRIGGERED`, expected `TRIGGERED`, finalized once), plus the same
  sequence for the top-level cardinal and the multiplicative, for zero, and a negative cardinal/fraction test.
- `ObliqueNumerator_GoesThroughTheAdjustFunction` (NTS-40) now also covers numerator 2 (UK, CS, SK), which #646 had
  avoided because of this defect.
- `ConvertOrdinal_WordRulesMatchBeforeAdjustFunction` is unchanged and green.
- New `NumberToStringNts43Tests` (13 methods, 41 cases): the UK/CS/SK feminine two and 2/3 (cardinal fragment with
  `IFractionLanguageSpecifics.NumeratorForcedVariants`, plugin oblique numerator), FR/ES/DE/EL/BG/FI gender and case
  morphology, an uppercase matrix (UK, CS, SK, BG, FR, ES, FI, EL: every variant combination, cardinals and
  multiplicatives equal the uppercased plain output), exact and generated scale forced variants, time-unit, clock,
  currency-subunit and fraction forced variants, decimals (language default and digit by digit), the minus template,
  and the EN `TWENTY-FIRST` ordinal.
