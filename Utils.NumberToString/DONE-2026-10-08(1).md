# Utils.NumberToString audit closures — 2026-10-08 (NTS-25A)

NTS-25A, the first part of NTS-25 (localized Conway names in derived scales), is closed. NTS-25 itself stays
open in `TODO.md` for NTS-25B (ID/MS localized tables, TR/SW alphabets). Sources are in
`docs/NTS-08-linguistic-sources.md`, section "NTS-25A".

## Project rule

When a language has adopted the mi/bi/tri/… large-number family, the library permits a productive
Conway-Wechsler extension using that language's own transliteration or adaptation of the prefix tables. This
is a generation convention of the library, not a normative claim about the languages: only the names a
language actually uses are sourced; the transliteration of the higher names must be consistent.

## Before

Names by Conway index n (RU/BG/UK were long scale: n = 10 was 10^60 and n = 1000 10^6000).

| Culture | 10^12 | n = 10 | n = 1000 |
|---|---|---|---|
| RU | биллион (long scale) | deciллион | миллиniллион |
| BG | билион (long scale) | deciлион | милniлион |
| UK | більйон (long scale) | deciльйон | мільniльйон |
| SW | trilioni | decilioni | minilioni (junction lost) |
| TR | trilyon | decilyon | minilyon (junction lost) |

## After

All five are short scale: Conway n is 10^(3n + 3).

| Culture | 10^12 (n = 3) | n = 10 (10^33) | n = 11 (10^36) | n = 106 (10^321) | n = 1000 (10^3003) |
|---|---|---|---|---|---|
| RU | триллион | дециллион | ундециллион | сексцентиллион | миллиниллион |
| BG | трилион | децилион | ундецилион | сексцентилион | милинилион |
| UK | трильйон | децильйон | ундецильйон | сексцентильйон | мільнільйон |
| SW | trilioni | decilioni | undecilioni | sexcentilioni | milinilioni |
| TR | trilyon | decilyon | undecilyon | sexcentilyon | milnilyon |

## Changes

- **`SCALE-SHORT-CYRILLIC`** (`NumberConvertionConfiguration.SCALE.xml`, `baseOn="SCALE-SHORT"`): the four
  Conway tables in Cyrillic, void group `ни`, the NTS-24 rules unchanged (`un` → `ун`, `(мс)вигинти`,
  terminal `[а|-illi=>и]`, single linking consonant, group restart through `Scale0Prefixes`). No
  `SCALE-LONG-CYRILLIC` was created: no Cyrillic language uses the long scale.
- **RU, BG, UK** now inherit `SCALE-SHORT-CYRILLIC` instead of `SCALE-LONG`, with static
  million/milliard and `startIndex="2"` (the Turkish model). The long scale contradicted these languages
  (10^12 is триллион/трилион/трильйон, 10^9 миллиард/милиард/мільярд); the three feature files asserting
  `биллион`, `биллиард`, `билион`, `билиард`, `більйон` and 10^18 `триллион`/`трильйон` were wrong and
  were corrected. BG overrides `UnitsPrefixes` (`кватуор`); UK overrides the four tables (і/и spelling,
  `кватуор`) and the void group (`ні`). Junctions: RU `лли` + `он`, BG `ли` + `он`, UK `ль` + `йон(ів)`.
- **SW**: `groupSeparator="li"` + suffix `oni` (was `""` + `lioni`); forms 1–999 unchanged.
- **TR**: `groupSeparator="l"` + suffix `yon` (was `""` + `lyon`); forms 1–999 unchanged. The
  accusative/dative rules for `trilyon`, `katrilyon`, `kentilyon` are replaced by one `EndsWith` rule on
  `yon` (last vowel o: `-u`, `-a`), so every generated name inflects (`seksilyonu`, `milnilyona`).
- **Engine (owner decision)**: Conway's x-link is two letters in Cyrillic (кс), but a marker inserted one
  character. A `(start)`/`(end)` marker list may now be comma-separated, each token being one marker
  (`се(кс,с)`, `(н,кс,с)центи`); without a comma every letter is still a marker, so the Latin tables are
  unchanged. The anchored grammar rejects empty tokens and leading, trailing or doubled commas. No public
  API change (ApiCompat strict against `master`: no breaking change), no XSD schema change (annotations
  only).

## Accepted limitation (owner decision)

The engine uses one `groupSeparator` between Conway groups and before the suffix. RU, BG and SW reproduce
the Latin `-illi-` in both positions; UK (`ль` + `йон`) and TR (`l` + `yon`) cannot, so 10^3003 is
`мільнільйон` and `milnilyon`, not `мілінільйон`/`milinilyon`.

## Left for NTS-25B

- ID/MS: `Scale0Prefixes` are localized (`kuadri`, `kuinti`, `seksti`, `okti`…) but the composition tables
  are the shared Latin ones, and `groupSeparator=""` still loses the junction above the 999th -illion.
  ID and MS output is identical to `master` (73-culture dump).
- TR/SW alphabets (owner decision, same iteration as ID): the shared Latin tables contain letters absent
  from Turkish and Swahili (q, x; Turkish c reads /dʒ/): TR `quattuordecilyon`, `sexcentilyon`,
  `decilyon`; SW `quadrilioni`, `quintilioni`, `sextilioni` (the SW 1–9 forms would change as well).

## Verification

- 73-culture before/after dump (74 after: `SCALE-SHORT-CYRILLIC` added): on the keys present in both
  dumps, only RU, BG, BG-BG, UK, UK-UA, SW, SW-KE, SW-TZ, TR and TR-TR changed; ID, ID-ID, MS and MS-MY are
  byte-identical. SW and TR differ only at scale indices above 1000. Other cultures differ only on the
  dump's random cardinals, whose values shift because the new culture consumes the shared random
  sequence (different numbers, not different output for the same number).
- `NumberToStringNts25Tests`: Cyrillic reference table (same indices as the NTS-24 Latin reference),
  multi-letter markers and malformed lists, RU/BG/UK exact names, script purity (no ASCII Latin letter in
  scale indices 1–2100, large indices and cardinals), SW/TR grouped names, TR case variants, `IsUnbounded`
  for the ten cultures. `NumberScaleContractTests` (NTS-24) unchanged and green.
