# Utils.NumberToString audit closure — 2026-10-13 (NTS-31, ordinal part: NTS-31 fully closed)

## NTS-31 — Dutch ordinals from a million

The cardinal part of NTS-31 (`DONE-2026-10-11(2).md`) left the Dutch ordinals explicitly guarded below one million
by `DutchOrdinalLanguageSpecifics`: no source then settled the ordinal of the scale nouns (*miljoenste* or *een
miljoenste*, *tweemiljoenste* or *twee miljoenste*). The ordinals now cover the whole `long` range, every value below
one million unchanged. The expectations were written in `Dutch.feature` and `NumberToStringNts31Tests` and ran red
(40 failures) before the production change. Sources: section "NTS-31 — Dutch ordinals from a million" of
`docs/NTS-08-linguistic-sources.md`.

### Sources

| Rule | Source |
|---|---|
| A derived ordinal keeps the spelling structure of the cardinal and ordinalizes its final element; the scale nouns take *-ste*: *miljoen → miljoenste*, *miljard → miljardste* | e-ANS (Algemene Nederlandse Spraakkunst), rangtelwoorden |
| *de twee miljoenste*, *de twee miljoen tweehonderdduizendste*, *de twee miljoen tweehonderdduizend tweehonderdtweeëntwintigste*: the multiplier stays a separate cardinal word, the earlier groups stay cardinal, no *en* between the groups | Besluit bekendmaking spellingvoorschriften 2005, rule 6.N |

Rules retained:

- round value, multiplier one: the scale noun alone (*miljoenste*, *miljardste*, not *een miljoenste*);
- round value, multiplier above one: the cardinal multiplier, a space, the ordinal scale noun (*twee miljoenste*, not
  *tweemiljoenste*);
- non-round value: every earlier group cardinal, only the final element ordinal (*een miljoen eerste*, *twee miljoen
  tweehonderdduizendste*). This is the usual last-word path, not `<OrdinalComposition>` (which ordinalizes several
  parts, as in Spanish).

### Implementation

- `NumberConvertionConfiguration.NL.xml`, `<Ordinals>`: stems `joen → joenst` and `jard → jardst` (the existing suffix
  `e` completes *miljoenste*, *biljardste* …), and `<OrdinalScale scales="2..6" multiplierSeparator=" " />`. Index 6
  (*triljoen*, 10^18) is the highest scale reachable by `long` (`long.MaxValue` = *negen triljoen …*); *duizend*
  (scale 1) stays on the cardinal path, which already drops *een* (*duizendste*). The stems only affect the last word
  (engine contract), so an earlier *miljoen* stays cardinal. No whole-number exception was added.
- `DutchOrdinalLanguageSpecifics`: retained as a documented guard with `SupportedDomain` 0–9223372036854775807 and
  `IsSupported` always true. Keeping it avoids a public API removal and leaves the lifecycle/finalization unchanged
  (`FinalizeWriting` is the identity). It receives the absolute value, so negative ordinals take the generic `min`
  prefix. The shared guard infrastructure is unchanged.
- No generic engine change, no Dutch-specific builder, no Conway/cardinal change (`suffixSeparator="l"`,
  *milliniljoen* unchanged).

### Tests

- `Dutch.feature`: the rejection scenario from a million is replaced by round scale ordinals (11 rows, multiplier one,
  multipliers above one, negative) and compound ordinals (7 rows, the three rule 6.N examples, `long.MaxValue`).
- `NumberToStringNts31Tests`: round scale ordinals to *negen triljoenste*, *een* dropped for multiplier one, spaced
  multipliers (not *tweemiljoenste*), compounds, a structural sweep over the `long` range (every word but the last is
  the cardinal), `long.MaxValue`, negatives, ordinals below a million unchanged, rejection beyond `long`.
- `NumberToStringOrdinalDomainGuardTests`: the NL row of the fail-closed test is removed (no Dutch value is outside
  the domain any more) and the NL largest validated value becomes `long.MaxValue`.
- `dotnet build Utils.sln -c Release`: 0 errors, no warning in the changed files. Unit 10 971/10 971, Functional
  383/383, Security 232 passed + 3 skipped.
- ApiCompat against master (dc904da8): no difference in non-strict nor strict mode (no public API change).
